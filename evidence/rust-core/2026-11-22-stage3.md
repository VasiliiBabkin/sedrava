# Sedrava native Rust migration — schema-1 snapshots + typed IR

**Date:** 2026-11-22. This is an engineering verification record for an
experimental implementation. It is NOT a complete language migration,
production certification or a portable crash-consistency guarantee.

## What changed

- Rust snapshot codec implementing the existing Python 0.11 schema-1
  signature, persistent state selection, bounded record/list values and
  validation; declaration order is preserved explicitly.
- Strict duplicate-key, float, unexpected-key, identity/type/resource-limit
  rejection when restoring JSON. Restorations are performed on a candidate
  state and must pass all rules.
- CLI option --state-file reads a compatible Python snapshot or writes a Rust
  snapshot only after accepted execution; replacement uses a same-directory
  temporary file, sync and atomic persist on the test Linux filesystem.
- CLI command ir exports a versioned experimental typed JSON intermediate
  representation, including partial top-level declaration source positions.
- Extra cross-language integration test (Python -> Rust -> Python and back)
  checks malformed snapshots and preservation of existing files on rejected
  actions.

## Critical limitations

- No SQLite/SQL connection is added to this language migration.
- No automatic change to published Python releases or Web/Android generators.
- No concurrent-writer coordination or multi-process serialization guarantee.
- No chaos/power-loss/disk-full recovery tests.
- No Windows/macOS durability certification or reproducible release build.
- Source spans describe top-level declarations only, not every expression.
- The JSON typed IR v1 is **experimental**, not a stable external compiler ABI.
- The differential harness compares the success/failure outcome for rejected
  cases; it does not prove equivalent error causes.

The migration issue #65 remains open until Web/Android generators, modules,
Site/WebApp DSL, Host effects and full release validation are complete.
