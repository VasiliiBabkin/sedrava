# Sedrava Native Rust — second migration increment (2026-11-22)

**Scope:** source implementation for records, typed bounded collections,
pure functions, deterministic stdlib, typed queries and navigation. This is
an experimental extension to the previously merged Rust scalar core; it does
not switch the default engine or imply full-language coverage.

## Verified environment

- Linux 6.8.0-147-generic x86_64
- Intel Xeon Skylake virtual CPU, 2 logical CPUs, approx. 7.8 GiB memory
- Rust 1.100.0; Cargo 1.100.0; Python 3.12.3
- User-local Rust install on disposable workspace on the connected VDS

## Measured CLI latency, not compiled application speed

The benchmark performs 5 warmups, then 30 subprocess runs per scenario and
engine, with randomized scheduling and a deterministic seed. It measures
process launch, dependency startup, parsing and the named CLI operation.
These numbers are the **medians on one VDS**, not universal speedups.

| Scenario | Python median (ms) | Rust median (ms) | Python/Rust ratio |
| --- | ---: | ---: | ---: |
| check reference | 250.9257 | 5.0467 | 49.721 |
| run reference | 249.6779 | 5.3640 | 46.547 |
| run Unicode profile | 243.3161 | 5.9971 | 40.572 |
| test reference | 224.7241 | 5.2524 | 42.785 |
| run records | 245.7526 | 5.9742 | 41.136 |
| run pure functions/queries | 239.3882 | 7.4404 | 32.174 |
| run navigation | 224.6018 | 3.6321 | 61.838 |

This does not establish faster generated JavaScript/Android apps, runtime
throughput under sustained workloads, or success on Windows/macOS.

## Important limitations

The native binary still lacks snapshot persistence, Web/Android generators,
Site/WebApp layout DSL, external modules, HTTP services, Host effects,
source-span diagnostic parity, and production/hardware verification.
No stable native release is published. Full coverage is tracked in
[the migration matrix](../../docs/RUST_FULL_MIGRATION.ru.md).

Initial development checks were executed in a disposable VDS worktree.
The complete Rust unit suite, build, differential checks, existing Python
regression suite and documentation checker were then **re-executed against
immutable commit `0ee0ebff13e972c02a84f16922f1959933f7990e`** in a
separate clean Git worktree. All checks listed above passed. No GitHub
Actions CI run was deliberately requested for this increment.
