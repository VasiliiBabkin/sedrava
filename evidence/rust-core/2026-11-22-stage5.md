# Sedrava Rust phase 5 — expanded native Web app generation

Date: 2026-11-22. **Status: experimental.** This is NOT a full Python
replacement, release candidate or proof of parity on every app or browser.

## Changes

The native Rust Web generator can now generate HTML/JS from tested
Sedrava app-mode fixtures with:
- persist schema-1 state with a fingerprint matching the Python/Rust
  snapshot codec; strict JSON parser detects duplicate keys, invalid
  schema, invalid values and incompatible signatures;
- prevention of deliberate overwrite when a saved value changed between
  load and save; no atomic multi-tab compare-and-swap guarantee;
- typed record constructors and record fields;
- bounded list operations with stable IDs, list selection and UI updates;
- function selectors and field selectors for filter/map/find/any/all/sort/sum;
- pure functions and scalar standard library including Unicode and dates;
- multiple screens, guards, navigation routes, back/pop and related actions.

The generated JavaScript and HTML are emitted from Rust source without
Python subprocesses. Existing Python compiler/build channels are unchanged.

## Unresolved release blockers

- No installed Chromium/Firefox/WebKit for real-browser tests on the VDS.
  Node mock-DOM acceptance is not a substitute.
- The Site and WebApp grammars, component/style expansion, routes/layout
  and static-site generator still require Rust implementations.
- No native Kotlin/Compose generator or Android APK/device testing.
- No native HTTP/API service DSL implementation or full Host effects/policy
  executor.
- Partial source spans, unstable IR and no complete fuzz/crash/property
  and Windows/macOS validation.
- No stable native binaries released; Python 0.11 remains the public default.

Issue #65 remains open. Do not publish a production compatibility claim.
