# Глава 2. Первое приложение с данными

Проверенная версия: Sedrava 0.12.0-alpha.4.

Счётчик из первой главы описывал состояние одной программы. Теперь создадим список контактов, записи которого сохраняются в отдельной базе. В декларативном проекте формата 2 сущность описывает однотипные записи, а поля — сведения о каждой записи.

Скопируйте каталог [examples/contacts](../examples/contacts/) в новый рабочий каталог. Он содержит два файла: domain.sdr и sedrava-project.json. Имя проекта в манифесте — book-contacts.

~~~sedrava
application "Контакты"
access session read write

entity person "Контакты":
    name: text 1 80 label "Имя"
    phone: text 0 40 label "Телефон"
~~~

Имя обязательно, длиной от 1 до 80; телефон может быть пустым. Телефон намеренно является текстом: плюс, ведущие нули и разделители не нужно превращать в число. access задаёт сессионный доступ для чтения и записи. Это не открытый сервер.

~~~sh
sedrava test
sedrava build
~~~

Команды выполняются в каталоге примера. В результате появится каталог build с идентификатором содержимого. В нём находятся app.sdr, api.sdr, migrations.json и UI. Здесь не нужно самому писать SQL, форму или HTTP-маршруты. Команда test проверяет генерацию и повторное применение миграций на временных данных, а не доказывает корректность всех бизнес-сценариев.

## Запускаем локально

Следуйте разделу «Локальный сервер» в [инструкции A39](../../docs/PLATFORM_RELEASE_A39.ru.md), заменив имя нового каталога данных на book-contacts-data. Подготовьте собственный случайный ключ, примените миграции, запустите serve с --allow-write. Только локальные тестовые данные. Не помещайте ключ в исходники и не открывайте сервер наружу.

После входа в alpha.4 вручную загрузите список. Введите новый уникальный ID, имя и телефон, сохраните запись. После подтверждения ранее загруженный список обновится автоматически. Попробуйте пустое имя: сервер должен отклонить запись. Повторный ID не создаёт вторую запись. Данные сохраняются после перезапуска сервера с тем же каталогом.

## Что уже сделано за нас

Компилятор создаёт таблицу, миграцию, API чтения и создания, типизированную форму и обновление списка. В этой версии нет общего редактирования и удаления сущностей формата 2. ID и первоначальную загрузку пока задаёт оператор. Это не полноценная промышленная адресная книга.

## Задание

Создайте отдельный новый проект заметок на основе примера, изменив имя в манифесте и описание сущности. Используйте новый каталог данных. Не меняйте схему уже существующей базы с ценными данными: изменение ограничений может быть несовместимым.
