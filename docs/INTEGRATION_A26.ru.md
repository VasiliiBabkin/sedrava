## Исправление A26

Два проекта с одинаковой схемой могли по ошибке указать одну директорию данных. Теперь migrate --apply связывает только пустой журнал с именем проекта первым durable batch. Проверяется единственная запись revision=1, receipt с sequence=1 и совпадение полного результата. migrate status/apply и project serve проверяют marker на открытом NativeLog под его эксклюзивной блокировкой. Другой проект или заполненный непривязанный журнал отклоняется до применения миграций и старта HTTP. Отказ оставляет байты БД неизменными. Прежний низкоуровневый database-api run сохраняет контракт и не требует marker. Это не граница безопасности против доверенного оператора с прямым доступом к raw namespace и не защита двух приложений с одинаковым именем. Намеренная несовместимость с экспериментальными проектными БД A25: автоматическая привязка заполненной БД запрещена; нужен отдельный проверяемый импорт. Не удалять старую БД ради запуска.
