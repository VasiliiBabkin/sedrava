# Типизированные ошибки, Result и исчерпывающий match — A1

Экспериментальная зависимая ветка поверх Effects A1. Это не стабильный релиз,
не реализация Host API и не система выдачи полномочий.

~~~sdr
error closed ArithmeticError id "example.ArithmeticError":
    IntOverflow:
        left: int
        right: int
error open ReadTextError:
    FileNotFound:
        path: text
    InvalidEncoding:
        path: text
        encoding: text
~~~

Имена типов ошибок не могут перекрывать встроенные int/text/bool/list/Result/Error.

Точная форма: `error closed|open Имя [id "стабильный.идентификатор"]:`.
Объявления предшествуют функциям и состоянию. Не более 16 типов, 1–16 вариантов
в каждом, 0–16 разных полей `int`, `text`, `bool` на вариант. Имена типов, вариантов, полей и привязок имеют форму `[A-Za-z][A-Za-z0-9_]*`.
Имена вариантов и полей — ASCII-идентификаторы до 64 символов; ID — до 128 символов. Пустой
вариант записывается `Name:` без тела. Поля неизменяемы. Конструктор требует
точного набора именованных полей: `ArithmeticError.IntOverflow(left=x, right=1)`.
Неявных преобразований нет. Payload проверяется теми же int32/Unicode-лимитами.

`closed` фиксирует набор вариантов данной версии типа. Новый вариант делает
неполный `match` ошибкой компиляции; такое изменение публичного API несовместимо
без пересмотра обработчиков. `open` заранее требует завершающий `Err(error)`;
новый вариант попадает туда, а не в обработчик с совпавшими полями другого
варианта. Закрытый тип тоже допускает общий обработчик оставшихся вариантов.

ID по умолчанию: `entry.Name` для корневого файла, `module.identity.Name` для
модуля. Явный `id` сохраняет идентичность при переименовании или перемещении.
ID варианта — `IDтипа.Variant`. Путь файла, alias импорта, порядок объявлений,
название приложения и классы Python/JS/Kotlin в идентификатор не входят.
Повторение ID в одной программе запрещено. Несовместимое изменение payload
требует нового версионированного ID. Это пока контракт идентичности, а не
готовый формат сохранения ошибок: состояния Result/ошибок, JSON-декодирование
и миграции в A1 не поддержаны.

~~~sdr
fn checked(x: int) -> Result<int, ArithmeticError> effects pure = Ok(x) if x < 100 else Err(ArithmeticError.IntOverflow(left=x, right=1))
~~~

`Ok(value)` и `Err(typed_variant)` получают точную пару типов из сигнатуры
возвращаемого значения или параметра функции. Для пользовательских ошибок
успешное значение ограничено `int`, `text`, `bool`. Полноценных пользовательских
генериков, вложенного Result, списков ошибок и неявной конверсии типов ошибок нет.
Поле ошибки нельзя подделать строкой вроде `"INT_OVERFLOW"`.

Старые `Result<T, Error>`, `try_add`, `try_chr`, `try_at` сохранены. `Error` —
отдельная непрозрачная встроенная граница; объявлять собственный тип `Error`
нельзя. `result_ok` и `result_or` работают с обеими семьями, `result_code` —
только со старой. Адаптер строится явно: проверить старый результат и создать
конкретный новый `Err`. Пример `add_checked` в `examples/typed_errors_012.sdr`
сохраняет операнды переполнения. Чистые вызовы в однострочном адаптере могут
вычисляться повторно; все они учитываются в бюджете.

~~~sdr
action inspect:
    let result = checked(100)
    match result:
        Ok(value):
            total = value
        Err(IntOverflow { left, right: addend }):
            total = left + addend
~~~

`match` — оператор внутри действия, не выражение и не многострочное тело `fn`.
Выражение вычисляется один раз. `Ok` обязателен для любого Result. Для `closed`
нужны все варианты либо общий `Err(error)` для оставшихся; для `open` и старого
`Error` общий обработчик обязателен и должен быть последним. Дубликаты,
недостижимые ветви, неизвестные варианты/поля и перекрытие видимых имён запрещены.
Можно извлечь часть полей; `field: local` переименовывает привязку. Привязки
неизменяемы и доступны только в своей ветви. `error_id(error)` возвращает
стабильный ID варианта без доступа к полям неизвестного варианта.

JSON-коды `SDR-E1201` (тип/конструктор), `SDR-E1202` (Result), `SDR-E1203`
(match) сохраняют прежний envelope; префиксы сообщений — `E_ERROR_TYPE`,
`E_RESULT`, `E_MATCH`. Остальные коды диагностики не изменены. Они включают координаты
исходника, в том числе после импорта и гигиенического переименования. Общие
лимиты выражений, функций, вложенности и действий сохраняются. Статический
бюджет использует самую дорогую ветвь; runtime оплачивает выбор ветви и затем
исполненные операторы. Изменения откатываются целиком при ошибке/инварианте.

BudgetExceeded, PolicyViolation, CapabilityDenied, CompilerError и InternalError
зарезервированы для неперехватываемых сбоев движка. Переполнение при вычислении
поля конструктора не превращается в Result. В A1 нет try/catch движка.

Объявления ошибок и match не добавляют эффектов файлов, сети, Host или Server.
Принцип сохранён: тип определяет значения; эффект — допустимые действия;
runtime — реально выданные полномочия. Для Host A3 ещё нужны доверенные адаптеры
со строгим переводом только ожидаемых ошибок, отдельная валидация данных и
политика ID. Для Server потребуются независимые адаптеры и security-тесты;
серверные ветки этим изменением не затрагиваются.

Команды:

~~~sh
sedrava test examples/typed_errors_012.sdr
sedrava test examples/typed_errors_modules_012/main.sdr
sedrava effects examples/typed_errors_modules_012/main.sdr --target web
sedrava build web examples/typed_errors_012.sdr --output build/errors/index.html
sedrava build android examples/typed_errors_012.sdr --output build/errors-android
~~~

Фактические результаты и конечный SHA — в зависимом draft PR и
[TYPED_ERRORS_MATCH_012_STATUS.md](TYPED_ERRORS_MATCH_012_STATUS.md).

В A1 общий Err всегда последний, в том числе для closed. Выражения именованных
полей конструктора вычисляются в порядке объявления полей на всех платформах.

Совместимость имён: прежние функции и конструкторы записей Ok, Err, error_id
сохраняют лексический приоритет. Новый intrinsic доступен, когда имя не перекрыто;
значение/параметр вместо вызываемого имени не игнорируется. Теги образцов Ok/Err —
грамматика, а не вызовы функций. Старые правила имён других конструкций не менялись.

Effects учитывает проверенную привязку операции: позднее объявление функции
Ok/Err/error_id не меняет уже типизированный вызов intrinsic. Некорректные
метаданные операции отклоняются, а не считаются чистыми по совпадению имени.
