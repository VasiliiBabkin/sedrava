# Нативный namespace import — ограниченный этап Rust

Статус: **экспериментальный app-mode**, не стабильный API. Поддерживаются
обычный плоский импорт и новое имя пространства для одного локального файла.
Ни Python, ни сетевой реестр пакетов при сборке и запуске не нужны.

Пример: [examples/native_aliases/main.sdr](../examples/native_aliases/main.sdr).

```sedrava
import "faults.sdr" as faults
import "left.sdr" as left
import "right.sdr" as right
state total = 0
action calculate:
    total = left.twice(1) + right.twice(2)
```

Два модуля могут экспортировать одинаковые имена функций и записей.
Компилятор статически связывает `alias.Name` с отдельным внутренним
именем, пока модули ещё являются исходным текстом. Декларации,
типы, вызовы и конструкторы внутри модуля переписываются согласованно.
Текстовые литералы, комментарии и имена полей не переименовываются.

Поддержанные экспортируемые декларации: `fn`, `record`, `error`.
Импортируемое семейство `error` обязано иметь явный стабильный `id`.
Стабильный ID ошибки не зависит от алиаса: при переименовании импорта
потребитель не должен видеть другой номинальный ID.

Старый `import "module.sdr"` остаётся плоским. В этом режиме имена могут
конфликтовать, поэтому для новых модулей рекомендуется явный `as`.
Исходная программа должна сначала объявить типы ошибок/записи и
функции, а затем состояние и действия (текущее ограничение Rust parser).
В примере сначала импортируется модуль с `error`.

## Ошибки, которые отклоняются

- Неизвестные поля пространства имён, обращение к алиасу как к значению,
  повторяющийся/некорректный алиас, использование зарезервированного
  внутреннего префикса `__sdns_`.
- Экспорт `state`, `action`, `screen`, `rule` или `test` из библиотеки.
- `import`, `component`, `style` и повторное вложение импортов внутри
  *именованного* модуля; вложенные обычные плоские импорты имеют
  прежнее ограниченное поведение.
- Импорт ошибки без стабильного `id`, пересечение параметра функции
  с именем экспорта, повтор экспортируемых имён.
- Выход из директории проекта, symlink, путь с `..` или специальным
  компонентом. Локальная папка `vendor/` продолжает требовать
  проверяемый lock, если присутствует пакет.

Существуют жёсткие лимиты на количество файлов и размер исходника.
Временное переименование не даёт модулю новых прав или возможностей.

**Границы:** это не полноценные вложенные пространства имён, не
универсальная гигиеническая система символов и не 100% семантика
Python 0.12. Не поддерживаются namespace aliases для компонентов
Site/WebApp, произвольное экспортирование app-state или поддержка
разрешения имён по runtime. Карта строк после разворачивания импортов
не сохраняет исходные номера из нескольких файлов. Система не защищает
от злонамеренной конкурентной замены доверенной папки проекта.

## Проверка

```sh
cargo build --manifest-path rust/Cargo.toml --locked --bin sedrava-native
./rust/target/debug/sedrava-native check examples/native_aliases/main.sdr
./rust/target/debug/sedrava-native test examples/native_aliases/main.sdr
./rust/target/debug/sedrava-native run examples/native_aliases/main.sdr calculate populate
./rust/target/debug/sedrava-native expand examples/native_aliases/main.sdr
python3 scripts/verify_native_aliases.py
```

Тестовый скрипт использует Python только для **внешней приёмки**:
проверяемый Rust-компилятор для исполнения не требует Python/pip.
