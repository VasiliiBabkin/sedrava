# Extension and server boundaries / Границы расширений и сервера

**Integration contract, not a native-plugin or server SDK announcement.** Current executable support is limited to the checked interfaces below. No source declaration authorizes loading executable Python, JavaScript, Kotlin or a shared library into the compiler.

## Implemented interfaces

| Boundary | Input | Validation / authority | Result |
|---|---|---|---|
| Local `.sdr` module | Root-confined import of records/functions/components/styles | Source/depth/file/expansion limits, exact types, no mutable captures or host execution | Existing typed domain/presentation IR |
| Component | Literal text/int/bool and `ref` identifier parameters, one slot | Literal checks, safe identifier substitution, normal state/action/row-schema validators after expansion | Checked ordinary UI nodes, not raw HTML |
| Local presentation resource | Explicit CSS/image/font path | No symlink/root escape/remote CSS, byte/type limits, author trust, hashed output | Local asset plus deterministic manifest |
| Browser HTTP adapter | Explicit self/public HTTPS service, method/path, typed record body, exact response schema | Origin/CORS/CSP, omitted credentials, no redirects/secrets, timeout/cancel/sequence/JSON/byte/item bounds | idle/loading/success/error plus checked public data |
| Core backend | Typed expression/action AST | Shared operation semantics and bounds, whole-action invariant commit | Python state / JS / Kotlin |

The component registry and code generator helpers are internal compiler APIs, without a promised stable Python plugin ABI. Extending them requires reviewed compiler code and regression/conformance tests. A stylesheet cannot supply executable behavior. An HTTP response cannot install modules or silently assign domain state. `ref` is an identifier reference, not a source-expression escape hatch.

## Required interface before any server adapter can be called supported

A future separately versioned server adapter must declare and test all of these boundaries. They are **not implemented** by this preview:

1. **Routes:** fixed normalized route/method, typed bounded input and output schema, accepted content types, request limits, explicit expected error mapping and request cancellation/deadline. No implicit route-to-database mapping.
2. **Business logic:** a trusted server transaction boundary. Client invariants are not authorization; rejected requests cannot leave partially committed database changes. Idempotency/retry behavior must be declared for mutating endpoints.
3. **Storage:** durable transactional adapter, schema version and compatibility/migration/backup/restore policy, concurrency and failure guarantees. Browser localStorage is neither a database server nor a synchronization protocol.
4. **Authentication:** a maintained standard provider/protocol and library, independently configured at the trusted server. No home-grown crypto or browser-embedded client secret. Authentication and authorization are separate checks.
5. **Authorization:** server-side per-operation and per-resource policy using verified identity; deny by default. Never trust a client-supplied user/role/record owner.
6. **Secrets:** server environment/secret store references, redaction and least privilege, no copying into HTML/JS/source maps/manifests/client storage or build logs.
7. **Dependencies/services:** pinned supported libraries, provenance/license/vulnerability review, explicit network/filesystem/database permissions and resource budgets. A module import grants none of these capabilities.
8. **Evidence:** actual local-server integration/security tests, invalid requests, concurrency, rollback, cancellation, oversized/untrusted input, auth failures and secret-leak regression. A compiled stub or mock success cannot establish support.

Until such an adapter exists, use an independently secured server exposing the declared JSON API. This requires ordinary server engineering and is not automatically generated by `build webapp`.

## Русское пояснение

Работающие границы: проверяемые локальные `.sdr` модули; параметры/слот компонента и ссылки `ref`; доверенные локальные CSS/ресурсы; публичный типизированный browser HTTP; общее ядро выражений/действий. Сырые HTML/JS/Python из исходника не исполняются компилятором. Реестр компонентов — внутренний API, не стабильный ABI плагинов.

Серверный адаптер пока отсутствует. Для его поддержки потребуются отдельно проверенные контракты маршрутов/схем/ошибок/лимитов, транзакционной логики, постоянного хранилища/миграций/конкуренции, стандартного провайдера authentication, серверной authorization deny-by-default, безопасного доступа к секретам и аудита зависимостей. Нужны реальные интеграционные/security-тесты; моки и компилируемый каркас не подтверждают готовность. Клиентские инварианты не защищают сервер, localStorage не является общей БД, CSS/import не выдаёт серверные полномочия. Пока подключайте независимо защищённый JSON backend. Никакие секреты не должны попадать в клиентскую сборку, кеш или журналы.
