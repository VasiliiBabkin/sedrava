# Sedrava self-hosting A4 — layout tokens and arithmetic expression AST

Дата: 23 ноября 2026. Экспериментальное подмножество языка,
не реализация полного парсера и не самокомпиляция.

## Реализовано в самой Sedrava

examples/self_host/parser_a4.sdr — программа на Sedrava,
выполняемая Rust native CLI. Она сохраняет экспериментальный
лексер A3 с Token(kind,lexeme,offset,end,line,column) и добавляет
**два отдельных действия**:

1. scan_layout: независимо обходит исходный Unicode-текст в одном
   ограниченном цикле, выдаёт LayoutToken(kind,offset,line,column,level)
   с видами NEWLINE, INDENT и DEDENT.
   Отступ: строго 4 пробела на уровень, максимум 8 уровней;
   пустые и закомментированные строки не изменяют уровень.
   При уменьшении уровня создаются DEDENT, в EOF уровни закрываются.
   Токены layout пока в отдельной коллекции layout_tokens,
   НЕ объединены с основным tokens лексера. Нет полной проверки
   грамматики Sedrava, корректности двоеточия перед INDENT или
   табуляции по визуальной ширине.
   В этом эксперименте layout отвергает TAB, CR и кавычки внутри
   некомментированного кода, следовательно многострочные строковые
   литералы не поддерживаются в layout-проходе.
2. parse_binary: формирует типизированные ExprNode и
   ExpressionAssignment с сохранёнными исходными span.
   Поддерживает только две формы:
       name = INTEGER OP INTEGER              (OP = + - * /)
       name = INTEGER (+|-) INTEGER (*|/) INTEGER
   Второй вариант намеренно строит вложенный AST: сначала
   умножение/деление, затем сложение/вычитание, без вычисления
   арифметического значения. Выражения с иным числом слагаемых,
   скобки, unary, идентификаторы в операндах и произвольные
   приоритеты пока не поддерживаются.

Коллекция ExprNode использует **устойчивые ID**, а не индексы:
для первой формы результат имеет ID 3, для второй ID 5.
Реализация рассчитана только на **свежий запуск одного действия**;
повторные scan/parse не образуют полноценный API парсера.
Действия scan_layout и scan являются независимыми. Для тестов
parse_binary вызывается ровно после scan.

## Проверки

    source "$HOME/.sedrava-dev/env.sh"
    sedrava_target
    cd "$HOME/.sedrava-dev/sedrava"
    "$CARGO_TARGET_DIR/debug/sedrava-native" check examples/self_host/parser_a4.sdr
    "$CARGO_TARGET_DIR/debug/sedrava-native" test examples/self_host/parser_a4.sdr
    SEDRAVA_NATIVE_BIN="$CARGO_TARGET_DIR/debug/sedrava-native" python3 -B scripts/verify_selfhost_parser_a4.py

Python только задаёт контрольный набор и независимо вычисляет
ожидаемые токены/структуру AST. Сканирование и AST на тестируемой
стороне полностью выполняет исходный код Sedrava.

На VDS: 106 положительных и 10 отрицательных layout случаев,
12 положительных и 15 отрицательных AST случаев, детерминированные
результаты и позиции. A1/A2/A3 и 81 тест Rust также PASS.

## Строгие границы доказательства

- Максимум 256 Unicode-символов на вход, 100 токенов layout;
  вложенный цикл ограничен 8 итерациями уровня.
- Только ASCII-имена и целые литералы в арифметическом AST.
- NEWLINE/INDENT/DEDENT реализованы отдельным проходом, без
  склейки с существующим Rust lexer, без обобщённого парсера,
  type checking, IR, codegen и stage 1/2/3 self-hosting.
- Нет настраиваемой ширины табуляции, восстановления после
  синтаксических ошибок, AST произвольных операторов, функций
  или Unicode-идентификаторов.
- Старый стабильный Python Sedrava 0.11 и его публикации
  не изменяются и не поддерживают эти эксперименты.
