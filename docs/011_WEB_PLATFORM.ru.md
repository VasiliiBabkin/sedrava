# Sedrava 0.11: руководство по интеграционной Web-платформе

**Подготовка экспериментального релиз-кандидата 0.11.0rc1; публикация ещё не выполнена.** Эта ветка использует версию кандидата 0.11.0rc1, но опубликованный wheel 0.10.0 не содержит новые возможности. [Фактический статус](011_IMPLEMENTATION_STATUS.md), [подробный английский справочник](011_WEB_PLATFORM.en.md).

## Установка, сборка и первый запуск

Из интеграционного checkout, Python 3.10+:

```sh
python -m venv .venv
. .venv/bin/activate
python -m pip install .
sedrava check examples/platform_site.sdr
sedrava build site examples/platform_site.sdr --output build/platform/site
sedrava build webapp examples/platform_tasks.sdr --output build/platform/tasks
sedrava build webapp examples/platform_catalog.sdr --output build/platform/catalog
sedrava build webapp examples/platform_crm.sdr --output build/platform/crm
python -m http.server 8000 --directory build/platform
```

Откройте `/site/`, `/tasks/`, `/crm/`. Каталог ожидает независимо предоставленный HTTP endpoint `/api/products`: обычный статический сервер вернёт видимую ошибку. Браузерный тест предоставляет настоящий локальный тестовый сервер, который не является промышленным backend. Ручные исправления генерации не нужны.

`site` создаёт отдельные HTML-страницы, CSS и локальные ресурсы без JS runtime. `webapp` создаёт клиентское приложение с внешними index.html/app.js/app.css. Старые `app`, `check/run/test`, `build web/android` сохраняются. Для режимов представления предусмотрены check/build; терминальное выполнение интерфейса не имитируется.

## Логика, типы и функции

Сохраняются int32, text, bool, записи с именованными скалярными полями, ограниченные списки записей, устойчивые идентификаторы, инварианты и атомарные действия. Переполнение, неправильный тип и нарушение require/инварианта откатывают всё действие. Ошибочное промежуточное выражение нельзя скрыть последующим присваиванием.

Полный компилируемый пример:

```sdr
webapp "Counter"
fn incremented(value: int) -> int = value + 1
state count = 0
persist count
derive doubled = count * 2
rule count >= 0
action increment:
    let previous = count
    count = incremented(previous)
view main:
    container max 960 padding 24:
        column gap 16:
            heading "A typed counter"
            value count label "Count"
            value doubled label "Twice"
            button "Increment" action increment
```

`fn имя(параметр: тип, ...) -> тип = выражение` объявляется до состояния; типы параметров/результата — int/text/bool/объявленная запись. До 32 функций и 8 параметров. Разрешены вызовы ранее объявленных чистых функций; нет рекурсии, ссылок вперёд, захвата изменяемого состояния, выполнения Python/JS компилятором или неявных преобразований. Аргументы вычисляются один раз слева направо, включая неиспользуемые. `let` — неизменяемая локальная привязка с областью блока, без затенения состояния. `a if условие else b` требует bool и одинаковых типов ветвей; вычисляется только выбранная ветвь. Существующий оператор if/else внутри действий сохраняется.

`text_length` считает Unicode scalar values; `trim` удаляет только ASCII пробел/tab/CR/LF; `lower_ascii` меняет только A–Z; `contains`, `concat` сохраняют ограничения текста. `is_date/date_days/date_add` работают с реальными датами `YYYY-MM-DD`, годы 0001–9999; дни отсчитываются от 1970-01-01. Некорректные даты/выход за границы отклоняются. Неявных часов, часовых поясов и локалезависимого сравнения нет.

## Коллекции и преобразования

`filter/find/any/all/sort/sum` принимают строковый литерал существующего поля либо чистую функцию. Её первый аргумент — запись списка, остальные аргументы передаются явно. `map` принимает функцию, возвращающую объявленную запись. Полные исходники [задач](../examples/platform_tasks.sdr) и [CRM](../examples/platform_crm.sdr) показывают типизированный поиск и агрегирование.

`filter(list,"field",value)` сравнивает значения точного типа. `find` возвращает первый устойчивый ID или 0; any/all — bool, all пустого списка равен true. `sum` проверяет каждое сложение int32. `sort` стабилен, по возрастанию, текст сравнивается по Unicode codepoints. Filter/map/sort сохраняют ID, next_id и вместимость; map не создаёт новые идентификаторы даже при смене типа записи. Можно использовать функцию-предикат с параметром поиска. Непроверенные исполняемые лямбды не добавлены.

Список ограничен 1–100 элементами; действуют прежние ограничения записей, текста и хранения. Физический AST выражения — до 256 узлов, развёрнутая стоимость функций/запросов — до 4096. Дорогой запрос большой коллекции отклоняется компилятором.

## Модули и композиция

`import "assets/ui.sdr"` подключает локальный `.sdr` относительно импортирующего файла, внутри каталога входного проекта. Разрешены экспорты записей, чистых функций, стилей и компонентов. Запрещены symlink, выход за корень, циклы, повторяющиеся имена; до 32 файлов, глубина 16. Это плоское пространство имён, не npm/Python-загрузчик. Импорт состояния/действий и исполняемые плагины не реализованы. Диагностика развёрнутых компонентов пока использует номера строк развёрнутого текста: полная карта исходников остаётся ограничением.

Компонент объявляется `component Panel(title: text):`, тело содержит обычные компоненты и не более одного `slot`. Вызов `use Panel title "Обзор":` передаёт вложенное содержимое. `$title` подставляется вне строкового литерала как проверенный литерал. Параметры — точные text/int/bool, рекурсия запрещена. Параметр `ref` передаёт только безопасный идентификатор в типизированную позицию состояния/действия/поля строки: компонент `Metric(label: text, data: ref)` содержит `value $data label $label`, вызов — `use Metric label "Companies" data company_count`. Значение обновляется обычной реактивной привязкой; ссылка на действие проверяется обычным валидатором UI. Произвольные выражения/исходный код передать нельзя. Результат поступает в общий проверяемый AST интерфейса. Произвольные runtime value props, несколько именованных слотов и локальное состояние экземпляра пока не реализованы.

## Справочник интерфейса

Общие элементы: container/row/column/grid/card/callout, heading/paragraph/code, link/image, spacer/divider/navbar/footer. [Справочник статических свойств](WEB_UI_011.ru.md) описывает размеры, интервалы и адаптивные свойства. `class "my-class"` подключает проверенное имя класса к локальному CSS. У каждой страницы/экрана один заголовок h1; изображению нужен alt. Статическая button с `to` — ссылка, WebApp button с `action` — атомарное действие.

| Конструкция | Поведение |
|---|---|
| `value key label "Имя"` | Состояние или производное значение |
| `input key label "Имя" kind text` | Скалярный редактор; text/textarea/email/url; по умолчанию textarea |
| `checkbox key label "Включено"` | Bool |
| `select key label "Режим":` / `option "Первый" value "one"` | Типизированный выбор без преобразований |
| `form action save:` / `submit "Сохранить"` | Нативная форма, Enter, проверенное действие |
| `when flag:` | Условный вывод по bool |
| `dialog id confirm label "Подтверждение":` | Нативное модальное окно |
| `open "Открыть" to confirm` / `close "Отмена" to confirm` | Управление окном; Escape закрывает |
| `navigate "Детали" to details` / `back "Назад"` | Проверенный переход/история |
| `list tasks select selected title title status done` | Выбор по устойчивому ID |
| `table contacts select selected title name fields "name email" label "Контакты"` | Семантическая таблица с caption |
| `each tasks select selected title title:` | Собственный типизированный шаблон строки |

List/table/each поддерживают search/sort, `where поле equals состояние active bool_состояние`, `empty "Нет результатов"`, label. Поиск UI — фильтрация представления; для логики есть filter ядра. В each доступны обычные макеты, `field title label "Название"`, `row-when done:`, `pick "Выбрать"` и кнопки именованных действий. Выбор строки и действие применяются одним кандидатом; при отказе откатываются вместе. Вложенные row scopes, редакторы полей внутри строк и capability-элементы в шаблонах отклоняются явно.

Ошибочный черновик поля блокирует отправку действий/форм/запросов и переходы до исправления. Принятое состояние остаётся корректным. Черновики не обещано сохранять. Закрытие модального окна не откатывает уже принятые изменения — для такого поведения заведите явное черновое состояние и действие. Вкладки/боковые панели пока компонуются обычными макетами и переходами; отдельного примитива нет.

## Маршруты и жизненный цикл

`view main:` — начальный незащищённый `/`. `view details at "/tasks/:selected" when chosen:` использует изменяемый int-параметр и bool-guard. Цели, дубликаты экранов/маршрутов проверяются. Адреса hash-based (`#/tasks/1`), поэтому прямое открытие/перезагрузка работают на статическом сервере. Поддерживаются Back/Forward, глубина переходов до 32, фокус h1 после перехода и видимый фокус интерактивных элементов.

Все параметры маршрута применяются вместе к одному приватному кандидату, затем проверяются инварианты и guard. Перекрывающиеся литеральные/int-шаблоны маршрутов отклоняются. Отсутствующая/удалённая запись не повреждает состояние: показывается ошибка или основной экран. Удаление выбранной записи закрывает недоступный экран/диалог. HTTP отменяется при уходе с экрана/pagehide; устаревшие ответы подавляются. Произвольные строковые route-параметры и path-rewrite SPA пока не реализованы.

## Хранение и офлайн

`persist` использует точный fingerprint схемы и полную проверку восстановления. Повреждённое/несовместимое исходное хранилище сохраняется, дальнейшая запись блокируется. Автоматической миграции нет. Изменение схемы, имени приложения или пути размещения может менять совместимость/идентичность хранилища; делайте резервную копию отдельно. Browser storage локален для origin/path, не шифруется и может быть удалён браузером/пользователем.

Офлайн-поведение означает принятое локальное состояние и необязательный кеш публичного GET. Service worker для холодного скачивания страницы без сети не реализован.

## HTTP API

Полный [каталог](../examples/platform_catalog.sdr) объявляет GET/POST/PUT/PATCH/DELETE. Service содержит origin, path, method, timeout, max-bytes/max-items, response one/many со строгими полями int32/text/bool. Для POST/PUT/PATCH обязателен `body Product(title=product_title, available=product_available)` с проверенной записью. DELETE без тела. `auto true`/`cache true` — только GET.

`origin self` явно разрешает same-origin; иначе нужен отдельный публичный HTTPS origin. Параметры path `:state` — int. UI использует request/cancel/remote. Блок `remote ...:` позволяет задать собственный типизированный шаблон card/layout/field/row-when по схеме ответа, используя общий renderer строк. Недостоверный текст становится текстовыми узлами. Remote-шаблон не выбирает локальные ID, не редактирует состояние и не выдаёт права действий над записями.

Явные состояния idle/loading/success/error сохраняют последние принятые данные при ошибке. Ответ не записывается непроверенным в domain state. Для response many допускается пустой 204, для one — нет.

Проверяются HTTP status, схема/лишние поля, duplicate keys, глубина JSON, UTF-8, int32/text, лимиты элементов и потоковых байтов. Timeout 100–30000мс, ответ до 200000 байт, по умолчанию 65536. Credentials omit, redirects error, CORS/CSP соблюдаются. Нет обхода CORS, API-ключей/секретных заголовков или произвольного JS. Публичный GET-кеш показывается до явного refresh; повреждённый кеш не перезаписывается. Ключ учитывает путь приложения, схему/config и фактический endpoint с параметрами; смена параметра отменяет старый запрос и не принимает его запоздалый ответ. Отмена запроса не гарантирует отмену уже выполненной серверной мутации, распределённого rollback нет.

Тесты используют настоящий localhost HTTP-сервер, включая ошибки/неверные схемы/лимиты/timeout/cancel/retry/XSS. Это не доказательство защищённости чужого API.

## Стили, темы и ресурсы

`theme:` задаёт background/surface/foreground/accent/gold/muted/border. `style panel:` определяет повторно используемые проверенные свойства. В WebApp именованные `theme light:`/`theme dark:` и `theme-state theme_mode` связывают палитру с изменяемым text-состоянием; допустимые имена входят в инварианты ядра и проверку restore.

`stylesheet "assets/brand.css"` — доверенный авторский локальный CSS: до 8 файлов по 256KiB. URL ресурсов ограничены корнем, symlink/remote/import/escape и устаревшие исполняемые конструкции запрещены; имена копий зависят от содержимого. Это ограниченный формат CSS, а не универсальная очистка недоверенного стороннего CSS. Локальные WOFF/WOFF2 проверяются по сигнатуре; приложите лицензию шрифта. Изображения используют общий валидатор, общий предел ресурсов — 16MiB. CSS не выдаёт права JS/HTTP. Адаптивные свойства и media queries позволяют менять макет; базовый CSS учитывает reduced motion и клавиатуру. Автор отвечает за контраст своей палитры и смысл контента.

## Многостраничные сайты и SEO

Несколько `page имя at "/path/":` с title/description/lang создают обычные статические HTML. Общие компоненты/макеты импортируются, меню — navbar/link. При явном `origin "https://your-reviewed-host.example"` создаются canonical/OpenGraph, sitemap.xml, robots.txt. `robots false` запрещает индексацию и требует origin. `favicon "assets/icon.svg"`, `social-image "assets/cover.svg"` безопасно копируют ресурсы. Статические SEO-директивы в WebApp отклоняются, не имитируются. Генерация ничего не публикует.

## Расширения, серверная граница и развёртывание

Разместите просмотренный site-каталог на статическом хостинге. WebApp обслуживается по HTTP(S), hash-маршрутам не нужны rewrites. Для сохранения storage namespace сохраняйте origin/path/имя. Backend предоставляется независимо: авторизация, валидация, лимиты, журналы, транзакции и секреты должны проверяться сервером. Ограничения браузера не защищают сервер от другого клиента.

Реализованные расширения — compile-time `.sdr` библиотеки, локальные ресурсы и объявленные публичные HTTP capabilities. Будущий исполняемый/серверный адаптер требует отдельно версионируемого контракта: маршруты, типизированные запросы/ответы, ошибки/отмена/лимиты, транзакции, миграции, стандартная authentication/authorization, внедрение секретов и аудит зависимостей. Клиентская декларация этого не разрешает автоматически. Серверная бизнес-логика, SQL, auth и произвольные исполняемые плагины **не реализованы**. Не помещайте секреты в исходники клиента. [Политика безопасности](SECURITY.md).

## Переход и совместимость

Существующим 0.9/0.10 app-программам не нужно менять синтаксис: используйте прежние targets. Новые режимы/импорты не мигрируют прежнее состояние. Устанавливайте ветку в отдельное venv; для отката удалите его и вернитесь к закреплённой версии компилятора. Откат компилятора не является миграцией данных. Артефакты опубликованных версий не изменяются.

| Возможность | Web preview | Android |
|---|---|---|
| App 0.9/0.10, записи, списки, атомарность, навигация | Прежний Web сохранён | Прежний Compose сохранён |
| Чистые функции/let/условные выражения/запросы/даты | Python + JS | Kotlin backend/JVM oracle |
| Статические страницы, SEO, CSS/шрифты, композиция | site | Не Android target |
| Формы/таблицы/шаблоны/диалоги/hash routes/темы | webapp | Не переводятся в Compose |
| Типизированный HTTP | Публичные browser capabilities | Новый HTTP target не добавлен |
| Backend/auth/DB/native plugins | Не поддерживаются | Не поддерживаются |

Проверки включают полное состояние Python/JS/Kotlin, реальные сценарии Chromium, шесть ширин 320/360/390/768/1024/1440, скриншоты и axe-core четырёх начальных экранов. Это не полная сертификация accessibility. Точные числа и SHA — в файле статуса/CI. Firefox/WebKit, полные source maps, namespaced modules, runtime props, clock/timezone/форматы, серверные адаптеры и service worker остаются задачами. **NO-GO для выпуска 0.11.0 до выполнения критериев.**
