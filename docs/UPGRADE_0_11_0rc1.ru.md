# Проверка обновления 0.10.0 → неопубликованный кандидат 0.11.0rc1

Кандидат находится в PR #42 и **не опубликован**. Не используйте предполагаемый
пакет RC в PyPI или несуществующий тег. Скачайте wheel/sdist из успешного workflow
на точном SHA, проверьте commit и SHA-256, сохраните оба исходных архива.
Опубликованный пакет называется **`sedrava==0.10.0`**, не `sedrava-lang` и не 0.9.

## Сначала резервная копия

Храните проекты `.sdr` вне виртуального окружения. Скопируйте исходники, импорты и
ресурсы, старую генерацию, файлы CLI-состояния и исходные значения браузерного
хранилища. Сохраните Android application ID и ключ подписи. Автоматической миграции,
экспорта и ремонта данных нет. Не очищайте хранилище и не удаляйте Android-приложение,
чтобы выдать чистую установку за сохранение данных при обновлении.

## Рекомендуемый способ: отдельные окружения

```sh
python -m venv .venv-010
.venv-010/bin/python -m pip install sedrava==0.10.0
.venv-010/bin/sedrava --version
python -m venv .venv-011
.venv-011/bin/python -m pip install /absolute/path/sedrava-0.11.0rc1-py3-none-any.whl
.venv-011/bin/sedrava --version
.venv-011/bin/sedrava check /absolute/path/project.sdr
.venv-011/bin/sedrava test /absolute/path/project.sdr
.venv-011/bin/sedrava run /absolute/path/project.sdr
```

В Windows используйте `Scripts/python.exe` и `Scripts/sedrava.exe` вместо
`bin/python` и `bin/sedrava`. Запускайте команды вне checkout компилятора: иначе
Python может импортировать исходники вместо установленного пакета.
Для возврата активируйте `.venv-010` и совместимую сохранённую генерацию.
Новый синтаксис 0.11 `site`/`webapp` не обязан работать в 0.10.

## Обновление и обратная установка в одном venv

Заранее скачайте старый wheel и зафиксируйте хеш. В **одном и том же** тестовом venv:

```sh
python -m pip install /absolute/path/sedrava-0.10.0-py3-none-any.whl
sedrava --version
python -m pip install --force-reinstall /absolute/path/sedrava-0.11.0rc1-py3-none-any.whl
sedrava --version
python -m pip check
# Вернуть именно прежний пакет; проекты и сохранения не удалять.
python -m pip install --force-reinstall /absolute/path/sedrava-0.10.0-py3-none-any.whl
sedrava --version
python -m pip check
```

`sedrava run --state-file` записывает канонический снимок даже без действия;
это не команда просмотра файла без записи. Отвергнутый снимок приводит к ошибке
до замены файла. Перед запуском сохраняйте исходный файл.

Ожидаются версии `sedrava 0.10.0`, `sedrava 0.11.0rc1`, `sedrava 0.10.0`.
Независимый аудит проверяет удаление модулей кандидата при обратной установке,
полные состояния четырёх общих проектов и совпадение всех байтов генерации из
wheel/sdist и повторно установленной той же версии.

## Web: сохранения и границы совместимости

При замене старого HTML генерацией кандидата сохраняйте **origin, путь HTML и
точное название приложения**. Query и hash не выбирают другое хранилище. Смена
домена, пути или названия выбирает другой ключ без автоматического переноса.
Возврат совместимого старого HTML по прежнему адресу позволяет прочитать принятые
кандидатом совместимые данные. Копия исходника не заменяет резервную копию данных.

Проверяются настоящее хранилище и действия в браузере: Unicode, устойчивые ID,
переименование/выполнение/удаление, холодная перезагрузка и возврат старого HTML.
Повреждённый JSON, повторные ключи и несовместимый fingerprint отклоняются; исходные
байты остаются после попытки редактирования, перезагрузки и отката. Показанные при
ошибке значения по умолчанию — **не успешная миграция**. Перед восстановлением
совместимой копии сохраните отвергнутый оригинал.

Отдельно проверяется настоящая пересборка с вместимостью 100 → 99: даже данные,
помещающиеся в новый предел, отвергаются из-за подписи схемы; оригинал сохраняется.

Испытания относятся к неизменённым скалярным схемам 0.10 и схемам записей/навигации,
не к произвольной смене схемы или переносу `app` в `webapp`. См.
[точный контракт](COMPATIBILITY_010.md). Нет гарантий согласования параллельной
записи, сохранности при обесточивании, шифрования и синхронизации устройств.

## Android требует настоящего установочного испытания

Оба APK генерируются из одного проекта установленными опубликованным wheel и
wheel кандидата. Обязательны одинаковые application ID и подпись; проверяемый
переход versionCode — **10003 → 11001**. Сборка/JVM-тест не доказывает установку
и сохранность данных на устройстве.

Отдельный workflow использует чистый **эмулятор API35**. Данные создаются через
Compose UI 0.10; затем выполняется `adb install -r` без удаления/очистки. Проверяются
полные снимки и холодный запуск, изменение в RC, поворот/пересоздание Activity и
системный Back. Обычная установка меньшего versionCode через `adb install -r`
должна завершиться `INSTALL_FAILED_VERSION_DOWNGRADE`, сохранив данные.
`adb install -r -d` проверяется **только для debuggable APK с тем же ключом**:
это не обещание производственного отката через Play или на обычном устройстве.
Производственное исправление требует нового возрастающего versionCode и
совместимой схемы. Удаление приложения обычно удаляет и его данные.
Повреждённый/несовместимый снимок не должен перезаписываться после обновления,
перезапуска и debug-отката. Debug-подпись не является производственной подписью.

## Повторение и доказательства

```sh
python scripts/check_upgrade_011.py --candidate-dist /absolute/verified/dist \
  --candidate-sha FULL_40_HEX_SHA --work /tmp/new-unique-upgrade-directory
python -m pip install playwright==1.62.0
python -m playwright install chromium
python scripts/test_upgrade_011_browser.py --work /tmp/new-unique-upgrade-directory
```

Каталог испытания должен быть новым и находиться вне checkout. Скрипт скачивает
настоящий пакет PyPI и проверяет фиксированные хеши. Для следующего кандидата
того же контракта предусмотрен `--candidate-version`. Read-only `upgrade-011.yml`
собирает одну пару архивов, передаёт точные файлы/генерацию в браузерные и Android
задания и формирует машинный итог на точном SHA. Публикации в workflow нет.

См. [аудит и исходные хеши](UPGRADE_AUDIT_011.md), [английскую инструкцию](UPGRADE_0_11_0rc1.en.md)
и [условия выпуска](RELEASE_TRACK_011.md). Технический GO не разрешает публикацию.
