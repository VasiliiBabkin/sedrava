# Native Server A11 — read-only индекс SedravaSQL

Экспериментальная интеграция через настоящий Rust API `sedravasql::native_log::index::VerifiedIndexReader`. Sedrava фиксирует зависимость на B12 `e2088d41ece67aac9b7c51f9280f1f37e7f204c0`; lockfile соответствует этому commit. Для запуска необходимы оба флага `--native-index ABSOLUTE_PRIVATE_INDEX --native-index-sha256 LOWERCASE_SHA256`. Файл полностью проверяется и сверяется с явно утверждённым SHA-256 до открытия loopback HTTP-сокета. Режим эксклюзивен: запрещены транзакционный режим, journaled, state-dir, SQLite backends и все маршруты кроме GET без изменяющих шагов. При выборе A11 SQLite-база не создаётся и не открывается, но сборка Sedrava по-прежнему включает зависимость rusqlite для старых режимов.

DSL `db_get`/`db_revision` не меняется. До формирования ответа считывается до 16 уникальных ключей из одного проверенного неизменяемого индекса. Tombstone или отсутствующий ключ -> 404 DB_KEY_NOT_FOUND; ошибочная строка, нарушение идентичности или приватности файла -> 503 DB_READ_FAILED и остановка poisoned-сессии. Ограничения текста/ревизии A10 сохранены; зарезервированные пространства имён запрещены. Изменение исходного журнала после создания индекса не меняет утверждённый снимок. Это чтение офлайн-снимка, не live NativeLog, не SQL и не замена A8/A9 транзакциям. Публичный HTTP-доступ, авторизация, запись, автоматическое обновление индекса не реализованы. Доверенный приватный неизменяемый файл и доверенный оператор обязательны.

Пример: `examples/native_server/native_a11_index.sdr`. Для теста на VDS собрать Sedrava и native preview SedravaSQL из закреплённого B12, задать `SEDRAVA_NATIVE_BIN`, `SEDRAVASQL_NATIVE_BIN`, запустить `python3 -B scripts/verify_native_server_index_a11.py`. Только временные приватные каталоги и локальные TCP-соединения. Тест проверяет много ключей/ревизий, 404, 405, 503, запрет режима записи, ошибки startup, фиксированный снимок, повреждение файла после открытия и отказ при повреждённом индексе.

VDS: свежая offline Rust debug-сборка с B12; 83 Rust-теста PASS; A11 real HTTP CLI PASS. A10 SQLite-regression PASS: 242 согласованных HTTP GET при 81 атомарном поколении записи, проверка аудита/receipts, tombstone и overflow. A11 не изменяет существующий SQLite API.
