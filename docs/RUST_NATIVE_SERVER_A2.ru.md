# Sedrava Server A2 — проверяемое состояние и ограниченное сохранение

**Статус:** экспериментальный loopback-only runtime, не production.
A2 расширяет A1, не меняя базовую Python 0.11, nginx или Host API.

## Синтаксис

Пример: [counter_a2.sdr](../examples/native_server/counter_a2.sdr).

```sedrava
server "Counter A2"
state count: int = 0
state label: text = "new"
route GET "/counter":
    respond 200 { count: state.count, label: state.label }
route POST "/increment":
    request delta: int
    require request.delta > 0
    set count = state.count + request.delta
    require state.count <= 5
    respond 200 { count: state.count, accepted: true }
```

- До 16 состояний типа `int` (signed int32), `bool`, `text`
  (не более 1024 Unicode-символов, без управляющих символов).
  Объявления должны находиться **перед маршрутам**.
- `set NAME = expression` меняет только объявленное состояние;
  `require expression OP expression` проверяет условие, где
  OP: `==`, `!=`, `<`, `<=`, `>`, `>=`. Для порядка — только int.
- Выражения: типизированный литерал, `request.FIELD`, `state.FIELD`,
  либо одно сложение двух int32 через ` + `. Нет произвольных
  вызовов функций и пользовательского выполнения кода.
- Не более 32 шагов на обработчик; `respond` — ровно один и последний.
  `GET` не разрешается изменять состояние.
- Весь обработчик работает с отдельной копией состояния. Поздний
  `require` либо арифметическое переполнение не публикует
  промежуточные изменения (HTTP 422, `GUARD_REJECTED` или
  `INTEGER_OVERFLOW`). Ответ читает уже обновлённый кандидат.

## Без сохранения — только память процесса

```sh
sedrava-native server check examples/native_server/counter_a2.sdr
sedrava-native server run examples/native_server/counter_a2.sdr \
  --port 8081 --max-requests 20 --idle-ms 30000
```

При штатном перезапуске без сохранения значения будут начальными.

## Сохранение в приватный каталог (опционально)

Создайте заранее отдельную папку, принадлежащую пользователю процесса
и имеющую права 0700. Путь должен быть абсолютным и каноническим,
без symlink и `..` в компонентах.

```sh
mkdir -m 700 /ABSOLUTE/TRUSTED/private-state
sedrava-native server run examples/native_server/counter_a2.sdr \
  --port 8081 --max-requests 20 --idle-ms 30000 \
  --state-dir /ABSOLUTE/TRUSTED/private-state
```

Сервер обращается только к двум фиксированным именам в этой папке:
`sedrava-state-v1.json` и `.sedrava-server.lock`. Язык не имеет
произвольных операций записи файлов; это не Host или SQL API.

- Перед запуском строго проверяются владелец/режим каталога, а также
  тип файла состояния, единственная жёсткая ссылка, права 0600 и
  отсутствие symlink. Путь с символическими ссылками и неподходящие
  права отклоняются. Состояние ограничено 16 KiB.
- JSON-снимок содержит `schema`, `signature` и `state`. Подпись
  привязана к имени сервера и объявлениям состояний с их
  первоначальными значениями. Несовместимая схема, повторяющиеся
  ключи, float, лишние поля, неверные типы и повреждённый JSON
  отклоняются **без запуска HTTP-порта**.
- Два одновременно запущенных экземпляра не могут использовать
  один каталог: второй отказывается от эксклюзивного lock-файла.
  После штатной остановки lock удаляется. После аварийного завершения
  lock **может остаться**: удалять его вручную разрешено лишь после
  проверки отсутствия другого работающего процесса.
- При сохранении создаётся временный файл в том же каталоге, который
  синхронизируется и атомарно заменяет прежний JSON; затем
  синхронизируется каталог. Если запись не дошла до замены, HTTP 503
  `STATE_WRITE_FAILED`, состояние в памяти не меняется.
- Если неудача возникла **после атомарной замены** при синхронизации
  каталога, исход записи неопределён: HTTP 503
  `STATE_COMMIT_UNCERTAIN` и сервер прекращает обработку.
  Это **не** гарантированный откат дискового состояния.

**Важные пределы:** нет exactly-once. После записи ответ может
потеряться, и повторный POST применит изменение ещё раз. Не проверены
отключение питания, файловые системы с иной семантикой синхронизации,
восстановление после SIGKILL, конкурентная замена файлов процессами
того же UID. Каталог должен считаться доверенным, недоступным
локальному злоумышленнику. Ручной stale-lock recovery несовместим
с автоматическим production-restart.

A2 остаётся последовательным сервером только на 127.0.0.1; лимиты
HTTP/1.1 и таймауты A1 сохраняются. Нет TLS, авторизации, публичного
доступа, параллельных транзакций, SQL, SedravaSQL, SQLite или
произвольного Host/сетевого доступа. Это экспериментальная основа,
**не полноценная СУБД или серверная платформа**.

## Приёмка

```sh
cargo test --manifest-path rust/Cargo.toml --locked --all-targets
python3 scripts/verify_native_server.py
python3 scripts/verify_native_server_a2.py
```

Python требуется лишь внешнему тестовому клиенту. Rust-сервер
исполняется без Python и Rust в PATH. Проверяются реальные HTTP-запросы,
поздний отказ/переполнение, сохранение после перезапуска, испорченные
данные, права файлов, lock и отказ записи. Полная crash-durability
не утверждается. Продолжение миграции: Issue #65.


Продолжение: [экспериментальный Server A3](RUST_NATIVE_SERVER_A3.ru.md)
добавляет идемпотентные квитанции и глобальную ревизию. Формат
A2 автоматически не обновляется до A3.
