# A16 — explicit native SQL host domain

A separate experimental `.sdr` domain, not a general app/Host/Server builtin. `database NAME` followed by four-space `param NAME: int|bool|text` lines and one `query "SELECT ..."` or `execute "..."` (JSON string). Parameters bind to `?` in declaration order; caller uses named `--arg NAME=JSON`. No interpolation, multiple SQL statements, arbitrary IO, network or implicit database path. `sedrava-native database check FILE` checks syntax/parameter count/statement class without a database; schema-specific checks occur during execution. `sedrava-native database run FILE --database ABSOLUTE_FILE --trusted [--arg NAME=JSON ...]` for reads; writes additionally require `--allow-write --request-key KEY`. Trusted local single-owner journal only. Stable request key retries preserve exact affected/sequence; write errors must not be interpreted as certainty for I/O failure. CLI values may be visible in process listings; do not pass secrets. Examples in examples/database. Existing SQL restrictions apply. No production or hostile-program sandbox claim.
