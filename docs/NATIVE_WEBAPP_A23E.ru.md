# A23e — авторизованный WebApp на Sedrava

Кандидат расширяет существующие типизированные браузерные HTTP-сервисы. Новый пример `examples/sales_demo/native_app.sdr` задаёт интерфейс входа, чтение каталога с курсором и добавление товара. Компилятор генерирует HTML/CSS/JS; отдельного рукописного JS приложения нет. Генерируемый runtime по-прежнему JavaScript. Полный старый интерфейс продаж (заказы, редактирование, отчёты) ещё не перенесён.

## Контракт

- `session "Ключ доступа"` — один контрол в main view, если есть сервисы с auth session. Парольное поле не часть состояния или persist. Вход и выход используют фиксированные серверные маршруты A23d.
- `auth session` — запрос с временной сессией, origin self; нельзя использовать auto или persistent cache. Постоянный ключ только для входа, временный токен только в памяти. 401 защищённого сервиса сбрасывает сессию и результаты защищённых сервисов; неопределённые записи сохраняются до явного выхода/перезагрузки. Если сервер уже отозвал сессию, logout с 401 также очищает локальное состояние.
- `body-field NAME EXPRESSION` — до 32 различных полей JSON, выражения int/text/bool. POST/PUT/PATCH, несовместимо с body. Это позволяет явно передавать поле id без изменения зарезервированного поля записей Sedrava.
- `response sql-rows:` — массив записей из строго проверенного объекта kind/columns/rows, с точным порядком объявленных столбцов, числом полей, scalar types и max-items. Допускаются rows/join_rows/aggregate_rows; null и неподдерживаемые типы отвергаются. Кеш запрещён. Это не универсальный SQL-клиент и не исполнение SQL в браузере.
- `idempotency true` — защищённые POST/PUT/PATCH. При неопределённом ответе сохраняются исходные параметры, principal и случайный request key в памяти конкретного сервиса. Повтор с изменёнными параметрами или другим principal блокируется. Известный окончательный отказ либо корректный ответ освобождает ключ. Явный logout, перезагрузка и закрытие страницы уничтожают локальный ключ; автоматического повтора нет. При просроченной сессии возможен повтор после входа тем же principal. Это опциональный контракт, не автоматическая защита произвольного API.

WebApp раздаётся нативным database-api через --web-ui: /, /app.js и /app.css (прежние /ui-script и /ui-style сохранены). Только точные статические имена; произвольные файловые пути не разрешены. Сохраняются ограничения размера ресурса, same-origin, CSP и loopback-only. Данные NativeLog и формат SQL не меняются.

## Воспроизведение

Собрать CLI по инструкции проекта, создать приватную тестовую БД и файл авторизации по A22/A23d, затем:

```bash
sedrava build webapp examples/sales_demo/native_app.sdr --output "$PWD/build/native-sales"
sedrava database-api run examples/sales_demo/sales_api.sdr \
  --database "$DB" --trusted --allow-write --auth-file "$AUTH" \
  --web-ui "$PWD/build/native-sales" --session-ttl 900
```

DB и AUTH — абсолютные пути к заранее инициализированным тестовым данным. Открыть напечатанный loopback URL на той же машине.

```bash
export SEDRAVA_NATIVE_BIN=/absolute/sedrava
export SEDRAVASQL_NATIVE_BIN=/absolute/sedravasql-native-preview
python3 -B scripts/verify_native_sales_a23e.py
# Node 20+, jsdom 27.2.0, NODE_PATH на node_modules:
SEDRAVA_A22_DOM=1 python3 -B scripts/verify_native_sales_a23e.py
```

Проверены повторные вход/выход после внешнего отзыва. Проверка БД завершена. Предшествующие A17–A23d: 296 прямых HTTP запросов и A22 DOM/HTTP PASS до финальной правки обработки logout; финальная правка повторно проверена целевым A23e. ## Границы

Проверка через jsdom, не Chromium. Нет браузерного подтверждения CSP, полной навигации каталога кнопками, CRUD заказов в native_app, универсального хранения сессий или публичного TLS. Результаты защищённого сервиса могут оставаться на экране до следующего запроса с 401/явного выхода; сервер всё равно проверяет срок. Заранее заданный session endpoint и схема привязывают контрол к A23d; общий OAuth и пользовательские HTTP заголовки не реализованы. Прежний ручной UI оставлен как эталон. Вся работа на временных данных; main и версии выпуска не изменены. Независимая Forgejo CI остаётся неподтверждённой. Строгий Clippy ранее не проходил.

Final Rust workspace: 85 tests PASS, 0 failed.
