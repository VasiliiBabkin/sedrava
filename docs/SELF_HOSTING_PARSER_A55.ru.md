# A5.5 — составные выражения на Sedrava

Экспериментальный `examples/self_host/parser_a55.sdr` расширяет A5.4b, сохраняя отдельную проверку структуры блоков и первый структурированный диагноз. Синтаксический AST для RHS присваиваний поддерживает integer, identifier, boolean, unary (-/not), binary и group. Приоритеты от слабого к сильному: or, and, not, сравнения, +/-, */ и унарный минус. Операторы одинакового бинарного приоритета левоассоциативны, унарные — вложенные справа; сравнения без скобок не образуют цепочку. `not` допустим в начале логического операнда или группы, а не как непосредственный арифметический операнд. Для скобок сохраняются позиции, для унарных узлов left_id указывает на операнд, right_id=0. Действуют прежние лимиты 256 Unicode-скаляров, 100 токенов, 100 узлов, до 16 заголовков/присваиваний, глубина отступов 8. Сохраняются лишь literal-boolean if true/false и action NAME:; составные условия, вызовы, строки, типизация, разрешение имён и исполнение новым компилятором не реализованы. Синтаксис деления унаследован от A5.3/A5.4, хотя текущий Rust core не вычисляет оператор /; синтаксическая поддержка не означает семантический паритет.

Проверка: независимый рекурсивный Python oracle сравнивает AST, приоритеты, позиции и связность; 28 корректных / 16 некорректных выражений + 1 guard PASS на VDS с release-бинарником A5.4b. Запуск: `SEDRAVA_NATIVE_BIN="$CARGO_TARGET_DIR/release/sedrava-native" python3 -B scripts/verify_selfhost_parser_a55.py` после загрузки окружения. Не self-hosted compiler.

Повторный прогон на свежем debug-бинарнике A11 (зависимость B12) — 28/16 + 1 guard PASS. Регрессия A5.4b на release — 11/18 + 4 guards PASS.
