# Нативный Sedrava Host A2: JSON и каталоги

Это **экспериментальное расширение доверенного POSIX Host**. Оно сохраняет
протокол четырёх исходов `sedrava.host.execution.v1` из Host A3 и существующие
операции текстовых файлов. Программы Host не выполняются из WebApp или Android;
исходники должны быть доверенными, а файловые разрешения — выданы явно.
Это **не ОС-песочница** и не среда запуска чужого кода.

## Поддержанные операции

- `arg name: json` — строгий JSON-аргумент до 4096 байт.
- `read_json document from path` — чтение в отдельном JSON-типе Host.
- `json_get_text|int|bool|json name from document at key` — получение значения
  по строковому ключу объекта или целочисленному индексу массива.
- `json_count name from document` — количество полей объекта или элементов массива.
- `json_object name` — новый пустой JSON-объект.
- `json_set object.field = value` — добавить новое поле; повторение ключа запрещено.
  Значение — скалярное выражение или ранее объявленный документ.
- `write_json path = document` — записать один JSON-файл без замены существующего.
- `emit_json document` — завершить программу структурированным результатом.
- `list_dir entries from "."` (или допустимого пути) — отсортированный список
  `{"name":"...","kind":"file|directory"}`, не более 32 элементов.
- `mkdir path`, `rmdir path` — создать один каталог или удалить один **пустой**.

JSON принимает только `null`, `bool`, `int32`, текст, массивы и объекты;
отклоняются float, повторяющиеся ключи, некорректный UTF-8, недопустимые
суррогаты, превышение глубины (8), числа узлов (128), полей объекта (32),
скалярной длины строки (1024) и 4096 байт сериализованного документа.
Объектные ключи сохраняются без преобразования к числам.

В программе допускается только одна файловая мутация, которую Host
откладывает до успешного вычисления `emit`/`emit_json`.
JSON-поля и промежуточные документы существуют только в Host-сеансе.

## Разрешения и изоляция путей

Параметры CLI задаются независимо:

| Операция | Необходимые флаги |
|---|---|
| `read`, `read_json` | `--trusted --allow-read` |
| `list_dir` | `--trusted --allow-list` |
| `write`, `write_json` | `--trusted --allow-write` |
| `mkdir` | `--trusted --allow-write --allow-mkdir` |
| `rmdir` | `--trusted --allow-write --allow-rmdir` |

`--root DIR` задаёт корень. `--read-scope`, `--write-scope` и
`--list-scope` задают независимые вложенные пути относительно него.
Их значение по умолчанию — `.`. Для файловых операций запрещены
абсолютные пути, `..`, `.` как компонент пути, symlink и переход через
непроверенные директории. Для каталога можно перечислить сам scope с помощью
литерального пути `"."`. Многоссылочные файлы, FIFO и иные специальные
объекты отклоняются.

Создание/удаление каталога и запись JSON выполняются относительно
открытых дескрипторов каталогов с `NOFOLLOW`. Запись создаёт временный
файл с последующим `linkat` без замены назначения и синхронизацией.
Пустой каталог создаётся с правами `0700`. Ошибка
`DIRECTORY_NOT_EMPTY` относится к ожидаемым `failed`, а не к ошибкам движка.

Не обеспечены: защита от одновременной злонамеренной замены каталогов/точек
монтирования, полноценная изоляция процесса, тайм-ауты в недоверенной среде,
несколько операций записи в одной транзакции, запуск подпроцессов, Host-сеть,
Windows Host, JSON/Result как полноценные типы app-mode и криптографическая
проверка происхождения исходников. Ошибка синхронизации после изменения ФС
может давать `commit_state=unknown`.

## Пример

`examples/host_a2/host.sdr`:

```sh
mkdir -p build/host-demo/inbox build/host-demo/outbox
printf '{"title":"Example"}' > build/host-demo/inbox/config.json
./rust/target/debug/sedrava-native host check examples/host_a2/host.sdr
./rust/target/debug/sedrava-native host run examples/host_a2/host.sdr \
  --root build/host-demo --trusted --allow-read --allow-list --allow-write \
  --read-scope inbox --list-scope inbox --write-scope outbox \
  --arg input=config.json --result-protocol v1
```

Файловый результат появится в `build/host-demo/outbox/report.json`, если
отсутствует файл с таким именем.

Верификация в изолированном каталоге:

```sh
cargo test --manifest-path rust/Cargo.toml --locked --all-targets
python3 scripts/verify_native_host.py
python3 scripts/verify_native_host_a2.py
```

Реализация следует проверяемой грамматике отдельного Python Host A2
из экспериментального PR #54, но **полное совпадение всех кодов ошибок
и все сценарии Python 0.12 пока не доказаны**. Не считать реализацию готовой
к исполнению недоверенного кода.
