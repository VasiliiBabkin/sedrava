# A40a — начальная загрузка справочников

[Декларация](DECLARATION.ru.md). Первый срез A40 поверх опубликованного alpha.4, кандидат, не новый выпуск.

До: оператор входил, открывал раздел и нажимал «Загрузить список». После: при первой видимости раздела в авторизованной сессии компилятор и runtime загружают основной список сами. domain.sdr не меняется; у сгенерированных list_ENTITY появляется низкоуровневое свойство initial-read true, кнопка становится «Обновить список». Четыре справочника service_complete требуют на четыре ручных начальных нажатия меньше, если все четыре открыты. SQL, миграции, бизнес-правила и схема хранения неизменны.

## Контракт

- initial-read true только для GET/POST сессийных SQL-rows сервисов, которые являются tracked-целями refresh, без cache, auto и idempotency. Это явный низкоуровневый контракт чтения, а не универсальный анализ произвольного HTTP. Старое auto остаётся GET-only и не разрешается для authenticated services. Прикладной domain.sdr нового свойства не требует.
- Первый запрос отправляется только после входа и только при видимом списке, в пределах прежнего сетевого бюджета. Не более одного начального запроса для ранее не запрошенного списка в текущей сессии. При наличии pending записи новый начальный запрос отложен. Подтверждённые мутации используют существующий A35 refresh. Отмена запроса при уходе из раздела может вызвать возобновление при возвращении согласно прежнему контракту tracked reads. Нажатие «Обновить» при уже активном таком запросе не создаёт дубликат.
- Изменение курсора после первого запроса инвалидирует устаревшие данные, но не инициирует чтение по каждому вводу. Для загрузки страницы нажмите «Обновить список». Ошибка первого запроса не вызывает автоматического повторения; оператор может нажать кнопку вручную. Logout очищает намерения/данные; следующая авторизация вновь загружает видимый справочник. Нет polling, скрытых начальных загрузок или автоматических записей.
- Автоматизация относится только к основным спискам сущностей. Фильтры, история и отчёты по выбранной записи сохраняют явную загрузку. Не добавлены автоматические ID, время, аудит, новые CRUD или миграции. Сохраняются локальные ограничения alpha.4. Для нового поведения нужна пересборка пакета компилятором этой ветки. Опубликованные артефакты alpha.4 не меняются.

## Проверки

92 Rust, включая положительный и отрицательные варианты initial-read. Реальный Chromium: 16 запросов (включая ресурсы и сессии), отсутствие чтений до входа, первый видимый список, создание и refresh, изменение курсора без запроса, переключение разделов без polling, сетевой отказ без автоматического повтора, ручной повтор, отсутствие загрузки отчётов без параметров, logout, новая сессия. Первый Rust-прогон 89/92 выявил GET-only проверку общего flag; исправлено отдельным GET/POST контрактом без ослабления auto. Финальные результаты регрессии фиксируются отдельно.

Учебники в book пока привязаны к опубликованному alpha.4, а не этому кандидату. Изменять инструкции по начальной загрузке следует при следующем публичном выпуске.

Финальный прогон: A16–A38 и семь alpha gates — PASS. A38 на новом runtime: 90 direct HTTP, 27 jsdom HTTP, 35 + 9 Chromium requests; новый A40 browser — 16 requests. Все пять проверенных предметных деклараций побайтно неизменны. Функциональный GO для A40a, без independent CI/release GO; релиз alpha.4 не изменён.
