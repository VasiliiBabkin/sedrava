# Sedrava Host A2 — каталог, JSON и ограниченные полномочия

**Экспериментальный зависимый draft PR от Host A1.** Ни stable 0.11,
ни браузер, ни Android не получают файловые полномочия. Режим host
исполняется только по отдельной команде с явным доверием к исходнику.

## JSON

Строгий тип host-данных json сохраняет структуры из объектов, массивов,
строк, bool, int32 и null. Запрещены float/NaN, повторяющиеся ключи, числа
за диапазоном int32 и недопустимые Unicode-символы.

Новые инструкции:

- arg config: json — JSON-аргумент в командной строке (не для секретов).
- read_json config from "config.json" — чтение JSON из файла.
- json_get_text / json_get_int / json_get_bool / json_get_json
  name from config at "key" — точное извлечение по имени поля,
  либо по числовому индексу массива.
- json_count size from config — число элементов объекта или массива.
- json_object report — новый пустой объект.
- json_set report.title = title — добавление нового поля со строгим
  типом; повторная запись того же ключа отклоняется.
- write_json "report.json" = report — одна отложенная атомарная запись
  компактного JSON в UTF-8.
- emit_json report — окончательный структурированный JSON-результат.

Лимиты JSON: документ ≤4096 байт, 128 узлов, вложенность ≤8 уровней,
≤32 поля на объект, текстовые значения ≤1024 Unicode scalars.
Имена ключей не приводятся к числам автоматически. Допускаются только
последовательные инструкции и максимум одна операция изменения ФС.

## Каталоги

- list_dir entries from "." — вернуть сортированный список JSON-объектов
  {"name":"...","kind":"file|directory"}. Не более 32 элементов.
  Символические ссылки, специальные и многоссылочные файлы отвергаются.
- mkdir "name" — создать один пустой каталог (права 0700).
- rmdir "name" — удалить один пустой каталог.
- Нет рекурсивных операций, удаления файлов, автоматического создания
  родителей, обхода символьных ссылок или запуска процессов.

Все операции со средой выполняются через POSIX descriptor-relative API.
Перед выполнением каждой программы разрешения проверяются полностью.

## Разделённые разрешения

--root DIR задаёт доверенную рабочую директорию.
--read-scope DIR, --write-scope DIR, --list-scope DIR задают
**независимые относительные каталоги** под root. Пути в программе
интерпретируются относительно соответствующей области. Значение "."
означает root. Области не должны содержать символьных ссылок,
абсолютных путей или .. .

- Для read/read_json требуется --trusted --allow-read.
- Для list_dir требуется --trusted --allow-list.
- Для write/write_json требуется --trusted --allow-write.
- Для mkdir нужны --allow-write и --allow-mkdir.
- Для rmdir нужны --allow-write и --allow-rmdir.

Пример: examples/host_inventory_013.sdr

~~~sh
mkdir -p build/demo/inbox build/demo/outbox
printf '{"title":"Inventory"}' > build/demo/inbox/config.json
python sedrava_cli.py host check examples/host_inventory_013.sdr
python sedrava_cli.py host run examples/host_inventory_013.sdr \
  --root build/demo --trusted --allow-read --allow-list --allow-write \
  --read-scope inbox --list-scope inbox --write-scope outbox \
  --arg input=config.json
~~~

Результат — JSON в stdout и файл build/demo/outbox/inventory.json.
После ошибки вычислений запись не начинается. Успешное изменение одной
папки или файла — не атомарная транзакция нескольких ресурсов;
ошибка fsync после изменения может означать неопределённость результата.
Система **не является ОС-песочницей** для недоверенного кода.
Нельзя считать её защищённой от одновременной злоумышленной замены
компонентов дерева каталогов и монтирования. Нельзя использовать для
многоарендного выполнения, хранения секретов или автоматического
предоставления прав через HTTP/браузер.

Совместимость с namespace PR #47 и bounded-core PR #50/#51 ещё
нужно подтвердить; серверные PR #48/#49 не изменяются.
