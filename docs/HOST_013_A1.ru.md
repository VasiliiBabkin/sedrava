# Sedrava host A1 — доверенные локальные операции

Экспериментальный режим, не включённый в стабильную версию 0.11.0.
**Это не изолированная песочница ОС:** использовать только с доверенным
исходным кодом, доверенным рабочим каталогом и доверенным пользователем ОС.

## Разделение прав

Документы начинаются строкой host "Имя". Проверка выполняется через
sedrava host check file.sdr **без файловых эффектов**. Исполнение —
только через sedrava host run file.sdr с явными флагами:
--root DIR, --trusted, --allow-read и/или --allow-write.

Отсутствие соответствующего разрешения приводит к отказу до начала операций.
Обычные app, Web, WebApp, site и Android не получают host-функций и не могут
запускать host-документы. Произвольные Python, shell, subprocess, сеть и
чтение переменных окружения в языке host A1 отсутствуют.

## Синтаксис

- arg name: text|int|bool — объявление обязательного типизированного параметра
- let name = expression — чистое выражение Sedrava
- read name from expression — чтение UTF-8 файла из рабочей папки
- write expression = expression — путь и текст для одной записи
- emit expression — обязательная последняя строка, JSON-результат

Пример: examples/host_report_013.sdr

~~~sh
mkdir -p build/host-demo
printf 'Hello\n' > build/host-demo/input.txt
python sedrava_cli.py host check examples/host_report_013.sdr
python sedrava_cli.py host run examples/host_report_013.sdr \
  --root build/host-demo --trusted --allow-read --allow-write \
  --arg input=input.txt --arg output=report.txt --arg heading="Report: "
~~~

Результат выполнения — JSON с ключами result и written. До 16 аргументов,
64 операторов, 8 чтений, одной записи; содержимое файла до 4096 байт UTF-8
и до 1024 кодовых точек Unicode.

Исполнение файловых команд доступно только на POSIX. Пути относительно --root;
абсолютные пути, переход выше root, пустые компоненты, символические ссылки
и файлы с несколькими жёсткими ссылками запрещены. Применены dir_fd,
O_NOFOLLOW, проверка обычного файла, O_EXCL, fsync и атомарная замена одного
файла. Новый и заменённый файл имеет режим 0600.

Это **не гарантированная изоляция от злоумышленника, одновременно
перемещающего каталоги**, и не изоляция от прав самого ОС-процесса.
Здесь нет создания папок, бинарных файлов, нескольких транзакционных
записей, сети или исполнения сторонних процессов. Аргументы --arg видны
в списке процессов; для паролей и токенов этот способ не подходит.

Никаких merge, PyPI, тегов и production-развёртываний. Пространства имён
PR #47, ядро PR #50/#51 и серверные PR #48/#49 требуют отдельных
интеграционных проверок.
