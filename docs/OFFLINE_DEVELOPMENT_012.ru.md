# Sedrava 0.12: разработка без GitHub Actions

Этот временный режим нужен, когда лимит GitHub-hosted Actions исчерпан. Он не изменяет опубликованную 0.11.0, не отключает проверку в `main` и не разрешает выпуск без испытаний.

## Локальные проверки (Python 3.10+)

Из корня репозитория:

```bash
python scripts/offline_verify.py quick
python scripts/offline_verify.py full
```

`quick` запускает настоящие unit-тесты для ограниченного ядра 0.12, пространств имён, Effects, типизированных ошибок и Host A3. `full` запускает всю Python suite, затем проверку документации и аудит безопасности релиза. При первом сбое выполнение прекращается; пропущенные шаги **не отмечаются как успешные**. Отчёт сохраняется в `build/offline-verify.json` с исходным Git SHA, если Git установлен. Команда сама ничего не скачивает, не устанавливает и не вызывает Actions; однако тесты из репозитория не являются изоляцией от сети.

**Проверки на реальных браузерах, Android API35, Python 3.10/3.13, Kotlin, Node, чистой установке wheel/sdist и аудит безопасности человеком отдельные.** Успешное выполнение скрипта не подтверждает эти проверки и не даёт права выпускать `0.12.0a1`.

## Временная ветка без запуска CI

Ветка `dev/offline-012` основана на экспериментальном SHA PR #60. На ней для пяти исторических workflow с безусловным `push` задан `branches-ignore: [dev/offline-012]`. Это предотвращает обычные push-запуски именно для этой ветки, не меняя поведение `main` и других веток. Публикация из этой ветки не предусмотрена. Не создавайте PR до восстановления доступности CI: другие `pull_request`-workflow могут запуститься, а обязательные проверки релиза остаются неисполненными.

Продолжение разработки: локально исполнять `quick` при каждом изменении ядра и `full` перед подготовкой PR; хранить JSON-отчёты и журнал изменённых SHA. После восстановления CI повторить независимые матрицы Python/JS/Kotlin/Android/браузеры и packaging на **точном SHA** перед любым объединением или публикацией.
