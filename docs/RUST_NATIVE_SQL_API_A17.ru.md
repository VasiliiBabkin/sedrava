# A17 — SQL HTTP API preview

Separate `database-api NAME` source domain (not the stateful `server` DSL). Each `route POST "/path":` declares typed `param name: int|bool|text` and one static `query "SELECT ..."` or `execute "SQL ..."`, with positional ? values in declaration order. Requests require application/json object with exactly declared keys; duplicate keys and nonscalar inputs are rejected. Query results include native aggregate_rows. No request-provided SQL, interpolation, arbitrary execution, outbound IO, or arbitrary file paths. Example: examples/database/orders_api.sdr. `sedrava-native database-api check FILE` and `sedrava-native database-api run FILE --database ABSOLUTE_FILE --trusted [--allow-write] [--port N] [--max-requests N] [--idle-ms N] [--native-max-bytes N] [--native-max-transactions N]`. Existing private journal, exclusive owner, 127.0.0.1 only. Any mutation route requires explicit allow-write at startup. Not authentication or a public web server; do not expose via reverse proxy. Queries cannot use idempotency header. Writes require valid Idempotency-Key; scope hashes API name, route path and client key; changing API name/path changes scope, changed SQL/parameters with same scoped key conflicts. 507 capacity before write, 409 conflict, 422 invalid; other storage failures stop the server with 503. On uncertain result retry with same key only after operator review. Startup and shutdown use existing verified native journal. Limits apply; response max 64KiB. HTTP framing uses existing native bounded parser.

VDS: 14 real loopback HTTP requests (typed bindings, static SQL, scoped durable replay after restart, capacity, duplicate JSON keys and invalid inputs, aggregate response); A16, A15, B15a, A10–A13 regressions PASS. 83 Rust tests. Dependency 810d0a943177e5b7e826b010a70814304652504e.
