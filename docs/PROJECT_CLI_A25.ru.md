# A25 — проектный CLI: локальная full-stack платформа Sedrava

Экспериментальный проект формата 1: sedrava-project.json (format, name, version), app.sdr, api.sdr, migrations.json. Имена проектов — lowercase ASCII, цифры, одиночные дефисы, 1..48; version — три числовых компонента. Шаблон основан на проверенном sales_demo: каталог в нативном WebApp, API товаров и заказов, пять миграций. Существующие команды build webapp FILE, test FILE и sedrava.toml/lock сохраняются; новый манифест независим. A25 поддерживает автономный исходник без импортов/внешних ресурсов и ровно три сгенерированных файла.

## Создание и запуск

Команды выполняются на Linux с установленным собранным CLI A25.

```bash
sedrava new myapp
cd myapp
sedrava test
sedrava build
```

Создать отдельную приватную директорию данных (абсолютный путь, владелец — текущий пользователь, права 0700) и приватный файл авторизации согласно A23d (постоянные случайные ключи и SHA-256 хэши, роли read/write). Пример путей:

```bash
DATA="$HOME/myapp-data"
mkdir -m 700 "$DATA"
AUTH="$DATA/auth.json"
# Подготовить AUTH по SERVER_SESSIONS_A23D.ru.md; не добавлять ключи в исходники.
sedrava migrate --data "$DATA" --trusted --apply
sedrava migrate --data "$DATA" --trusted
sedrava serve --data "$DATA" --auth-file "$AUTH" --trusted --allow-write --port 8080
```

migrate --apply создаёт отсутствующий app.log и явно применяет добавочные миграции. Без --apply только проверяет существующую БД. serve не применяет миграции: проверяет версию, явное --trusted и --allow-write для API с записями, private auth; привязка 127.0.0.1. Дополнительные параметры --session-ttl (default 900 секунд), --max-requests (1000), --idle-ms (120000). A26: выделять отдельную директорию для каждого проекта. При первом явном migrate --apply пустой журнал привязывается к имени проекта одной записью с квитанцией. migrate и serve сверяют привязку под эксклюзивной блокировкой. Другие имена и ранее заполненные непривязанные журналы отклоняются. Это защита от ошибочного выбора базы, не криптографическая изоляция одноимённых проектов. Автоматическое принятие баз A25 не поддерживается. Рабочая БД не удаляется и не перезаписывается при сборке. Не выставлять preview через reverse proxy.

## Сборка и переносимый пакет

build создаёт build/<sha256> с четырьмя исходными файлами, ui/index.html, ui/app.js, ui/app.css и checksums.json. Идентификатор — SHA-256 файла checksums.json, который содержит хэши всех остальных файлов и версию компилятора. Повторная сборка проверяет точный набор файлов и байты; при изменении входа создаёт новый каталог, при повреждении существующего — отказывается. Старые сборки автоматически не удаляются.

```bash
sedrava package --output ../myapp-release
sedrava project verify-package ../myapp-release
cd ../myapp-release
sedrava serve --data "$DATA" --auth-file "$AUTH" --trusted --allow-write
```

package публикует новый каталог без перезаписи; только allowlist исходников, сгенерированные файлы, checksums.json. Не копирует произвольные файлы проекта, БД, auth, окружение или бинарник. Если автор сам записал секрет в разрешённый исходник, пакет его содержит: это не сканер секретов. Пакет требует совместимый CLI. Проверка повторно генерирует UI и сравнивает полный набор и содержимое с ожидаемым. Контрольные суммы не являются цифровой подписью и не защищают от замены всего пакета с пересчитанными хэшами. build/serve из пакета не создаёт build внутри него, а проверяет и использует ui. Операции new/package публикуют каталог атомарным rename NOREPLACE на поддерживаемой ОС; это не гарантия аппаратной durability после потери питания. Доверенные директории оператора, не допускающие конкурентной подмены путей. Не использовать непроверенные исходники.

## Проверки

test проверяет WebApp generation, API parse и применимость всех миграций на временной приватной NativeLog, побайтно неизменный повтор и native verify; не исполняет пользовательские функциональные тесты API/DOM и не проверяет схему каждого SQL запроса. Отдельная сквозная проверка:

```bash
export SEDRAVA_NATIVE_BIN=/absolute/sedrava
export SEDRAVASQL_NATIVE_BIN=/absolute/sedravasql-native-preview
python3 -B scripts/verify_project_a25.py
# Node 20+, jsdom 27.2.0, NODE_PATH:
SEDRAVA_A22_DOM=1 python3 -B scripts/verify_project_a25.py
```

Реальный сценарий: создание проекта, отказ повторной записи, детерминированная сборка, новая сборка после изменения, отказ повреждённой сборки/пакета, отсутствие посторонних файлов в пакете, проверка SHA-256, строгий манифест/симлинк/private data, миграции 5 версий, запуск из пакета, 7 прямых HTTP-запросов и A23e DOM с реальным API, неизменность пакета после запуска. Только временные данные. Первый прогон после правки не собрал актуальную версию, так как rustfmt не был в PATH до загрузки окружения; повторная сборка и targeted PASS.

Ограничения: локальный Linux preview, не публичное развёртывание, не installer/standalone executable, не сжатый архив, не подписанный release. Настоящий Chromium и независимая Forgejo CI не подтверждены. Версия CLI и main не изменены; SQL закреплён на 60a7d0488a23135fa064b7cf2496f93a78b519bd. Строгий Clippy всего языка ранее не проходил. 

Final regression: 85 Rust tests PASS, 319 counted direct HTTP requests A17–A25 PASS plus A22/A23e and DOM acceptance.
