# Security and dependency review / Безопасность

Sedrava 0.10.0 accepts a restricted typed AST with int32, bool, Unicode text, records and bounded collections; the 0.9 integer/boolean subset is a historical baseline. It never passes application source to Python `eval`/`exec`, a shell or a network service. Calls, attributes and arbitrary host access are rejected. Size, AST, nested-block, derived-expansion and interpreter-step limits bound common malformed inputs. This is not a certified sandbox; compile untrusted sources in an isolated process with time/memory limits.

Generators encode labels for HTML and Kotlin, including HTML script-end sequences and Kotlin `$` interpolation. Application identifiers do not become executable JavaScript fragments; Kotlin state names use a generated prefix. CLI uses `pathlib` rather than shell commands; user-selected output paths intentionally overwrite generated target files. Do not generate into a directory containing irreplaceable edits. No telemetry, accounts, advertisements or cloud runtime dependencies are added.

Python package runtime dependencies: **none**. Build tooling uses setuptools/wheel and CI additionally uses build/twine/Playwright. Apache-2.0 applies to Sedrava; these tools and generated Android dependencies retain their own licenses (setuptools MIT, wheel MIT, build MIT, twine Apache-2.0, Playwright Apache-2.0, tomli MIT (test-only on Python 3.10), Kotlin/AndroidX Apache-2.0, JUnit EPL-1.0). Android SDK/JDK/Gradle distributions have separate vendor terms; they are not bundled into the Python package. A debug APK contains third-party AndroidX/Kotlin code; retain transitive notices when preparing production redistribution.

The generated manifest declares no permissions; AndroidX can merge its own signature-level permission. Verify the actual APK with `aapt dump permissions`. UI persistence is unencrypted and not suitable for passwords/tokens. Do not put secrets into source programs; CLI prints application state intentionally. Error messages do not dump browser storage or environment credentials.

Known-vulnerability coverage: runtime Python dependency surface is empty. Direct Android versions are pinned, but this work does not establish that every transitive Android/Gradle/JDK dependency has no CVE. A complete Android advisory/SBOM audit remains open; do not describe compile/Lint success as a security certification. Update dependency versions in a tested change rather than silently tracking latest. Report suspected vulnerabilities privately to the repository owner before including exploit details in public issues.
