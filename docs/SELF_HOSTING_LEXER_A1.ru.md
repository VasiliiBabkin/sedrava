# Sedrava — лексер A1: ограниченный цикл внутри языка

Дата: 23 ноября 2026. Статус: **экспериментальный native-only синтаксис**. Это не полноценный компилятор и не релиз Python 0.11.

## Синтаксис

    action scan:
        while cursor < text_length(source) limit 256:
            let ch = text_at(source, cursor)
            cursor = cursor + 1

После условия обязательно указывать limit, целое число 1..256.
Условие имеет тип bool. На каждой итерации условие проверяется заново.
Если после достижения лимита оно всё ещё true, действие завершается
ошибкой While iteration limit exceeded.

Состояние приложения меняется только после успешного завершения всего
действия. Неверное условие, превышение лимита, require или ошибка
операции внутри тела не публикуют частичную транзакцию.

Общий лимит шагов MAX_ACTION_STEPS=10000, предел глубины вложенности 32.
Ограничение длины текста и ёмкости списка токенов сохраняется.
Локальные переменные из тела не доступны за его пределами.

Реализация находится в Rust модели/парсере/runtime, нативном
Web JavaScript и Android Kotlin кодогенераторах. Экспериментальный
IR-candidate по-прежнему явно отвергает неподдержанные инструкции.
Стабильный Python-интерпретатор ещё НЕ понимает этот синтаксис.

## Работающий лексер на Sedrava

Исходник examples/self_host/lexer_a1.sdr содержит action scan:
он вызывает text_at(), сам проходит весь текст циклом while и строит
список Token(kind,lexeme,offset). Проверочный Python-скрипт не
вычисляет токены приложения — он только формирует тестовые входы,
запускает Sedrava-native один раз на вход и сравнивает выход
с отдельным проверочным алгоритмом.

Подмножество грамматики прежнее: ASCII идентификаторы, числа,
пробелы и простые знаки (),=+,-. Кириллица, строки, комментарии,
сложные операторы, отступы и полная грамматика языка не поддерживаются.

## Проверки

    source "$HOME/.sedrava-dev/env.sh"
    sedrava_target
    cd "$HOME/.sedrava-dev/sedrava"
    cargo test --manifest-path rust/Cargo.toml --locked --offline --all-targets
    cargo build --manifest-path rust/Cargo.toml --locked --offline --bin sedrava-native
    "$CARGO_TARGET_DIR/debug/sedrava-native" run examples/self_host/lexer_a1.sdr scan
    SEDRAVA_NATIVE_BIN="$CARGO_TARGET_DIR/debug/sedrava-native" python3 scripts/verify_selfhost_lexer_a1.py

81 native Rust tests: цикл завершается на границе 5 итераций,
проверяет переход к инструкциям после цикла, ошибка при бесконечном
цикле и require не публикует кандидата, недопустимые параметры
цикла отвергаются на этапе анализа.

Лексер: 13 положительных и 8 отрицательных строк, повторяемость
вывода, отказ при лимите 256. Старый A0 тест всё ещё проходит.
Web: HTML/JS с циклом создан, синтаксис JS проверен командой node --check.
Android: Kotlin код с проверкой лимита создан, но Kotlin compiler не
установлен на VDS, полноценная сборка APK НЕ проверена.

Clippy без запрета предупреждений проходит. Строгий Clippy
-D warnings выявляет старые предупреждения в других частях проекта;
пока НЕ является зелёным gate всей системы.
