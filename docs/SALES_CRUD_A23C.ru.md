# A23c — CRUD и защита от устаревших данных

Добавлены три маршрута к A23b (223af48). Все — авторизованные POST с обязательным idempotency key; используются существующие последовательные транзакции SedravaSQL, без изменения SQL-движка и on-disk формата.

| Маршрут | Контракт |
|---|---|
| /edit-product | id, old_title, old_category, old_price, title, category, price; условный UPDATE по первичному ключу и всем прежним значениям |
| /delete-product | id, old_title, old_category, old_price; условный DELETE, FK RESTRICT |
| /delete-order | id, old_amount; условный DELETE при paid=false |

Конфликт предиката, отсутствие строки или нарушение FK возвращают 409 SQL_CONFLICT, журнал не меняется. Требования A23a проверяют новые значения; старые значения не нормализуются. Исторические квитанции возвращают первоначальный результат при совпадении запроса; другой payload с прежним ключом отклоняется. Повторное создание удалённого ID не поддерживается (tombstones).

Это оптимистическая проверка **значений**, не ревизии; ABA (изменение и возврат к прежним значениям) не обнаруживается. Переназначение товара в заказе и отмена оплаты не реализованы; корректировка суммы использует прежний /correct-order. Старый /mark-paid сохраняет контракт, включая возможность affected=0. Полное управление финансовыми записями и платежами не заявляется. DELETE не означает стирание истории из журнала. Исторические строки заказа используют текущее название товара из JOIN, не снимок названия на момент заказа.

Лимит маршрутов увеличен с 16 до 24: проверено принятие 24 и отказ 25. UI показывает редактирование товара и подтверждаемое удаление, не показывает кнопки удаления оплаченного заказа; права всегда проверяются сервером. Кнопка повтора использует сохранённый в памяти исходный path/body/key даже после обновления списка. После закрытия/перезагрузки страницы pending теряется. HTML/CSS/JS написаны вручную; реальные браузерные тесты CSP ещё нужны. API остаётся локальным, публичное развёртывание не выполнялось.
