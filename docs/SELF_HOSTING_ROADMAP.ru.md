# Sedrava — путь к самокомпиляции / self-hosting

Статус: **долгосрочная цель, не реализована**. 23 ноября 2026.

## Конечная цель

Компилятор Sedrava, **написанный на Sedrava**, должен самостоятельно
собирать свои исходники и другие программы без обязательного Python
или Rust runtime. До этого момента Rust остаётся bootstrap-инструментом.

Опубликованная Python Sedrava 0.11.0 остаётся самостоятельным
действующим стабильным релизом. Экспериментальный Rust compiler пока
не соответствует полному действующему контракту.

## Проверяемая последовательность

1. Стабилизировать в Rust проверяемое ядро языка, диагностику, типизацию
   и IR, определить допустимые несовместимости.
2. Довести Sedrava до функций, необходимых самому компилятору:
   двоичные файлы/потоки, структурированные ошибки, рекурсивные данные,
   эффективные коллекции, управляемая память, модули, эффекты,
   детерминированная сборка и кодогенерация.
3. Написать первый токенизатор на Sedrava и сравнить его с Rust.
   Затем парсер, AST, проверку типов, IR и ограниченный генератор.
4. Запустить stage 1: Rust-компилятор собирает компилятор на Sedrava.
   Stage 2: полученный бинарник собирает те же исходники сам.
   Stage 3: stage 2 повторяет сборку. Сравнить артефакты, тесты
   соответствия, диагностику и поведение на разных платформах.
5. Только после воспроизводимой сборки и полного gate отдельно
   решить, когда self-hosted реализация станет основным инструментом.

## Границы

Самостоятельный парсер на Sedrava ещё **не** является самокомпилятором.
Создание компилятора на Sedrava не подразумевает, что все
системные зависимости написаны на Sedrava — эти уровни различаются.
SedravaSQL не должна быть обязательна для сборки компилятора.

Нельзя объявлять self-hosting достигнутым только из-за наличия
Rust-ядра, экспериментальной базы или работающей демонстрации.

Паритетность Rust/Python/JS проверена; Kotlin компилятор не установлен на VDS, а внутренний цикл Sedrava и полноценная грамматика пока отсутствуют.
