## Что проверено на VDS

Синтаксис `while cursor < chars limit 256`, `text_at` и
вложенные `if` прошли проверку, тест исходника и нативный запуск.
Начальное `мама мыла раму` дало chars=14, spaces=2, letters_a=4,
runs=1. Из того же Sedrava-исходника сгенерирован Android/Kotlin
проект, который собран через `:app:assembleDebug` (PASS).
Проверены подпись v2 и корректность структуры APK.

**На реальном Android ещё не проверено** поведение интерфейса и
отдельные действия пользователя.

## Что проверить на смартфоне

1. Установить отдельный APK (не перезаписывает Daybook), открыть.
2. Нажать «Посчитать символы» для исходного текста:
   14 символов, 2 пробела, 4 буквы «а», запуск 1.
3. Изменить ввод на `кот 🐱`, нажать кнопку:
   5 символов, 1 пробел, 0 букв «а», запуск 2.
4. Ввести `Аа а` и проверить чувствительность к регистру:
   4 символа, 1 пробел, 2 буквы «а».
5. Нажать кнопку повторно. Счётчик запусков должен увеличиться.
6. Отметить, если появились ошибка, зависание, неправильное число или
   неожиданное закрытие. Скриншот поможет воспроизвести дефект.

Для этого испытания **не требуется повторять** вчерашние тесты
создания/редактирования/удаления задач и сохранения после закрытия.

Сейчас лимит длины ввода 256 символов. Ввод длиннее не входит в
сценарий ручного тестирования и должен получать отдельные
негативные проверки после согласования безопасного UI error flow.
