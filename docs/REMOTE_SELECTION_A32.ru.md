# A32 — типизированный выбор удалённых данных

Прикладной сценарий A31 выявил невозможность переноса полей SQL-ответа в форму. A32 вводит универсальную команду, а не специальный обработчик сервисного журнала:

```sedrava
remote tickets:
    field id
    field last_event
    remote-pick "Работа по заявке" bindings "id:event_ticket last_event:expected_event" action go_workflow
```

bindings — от 1 до 8 пар FIELD:STATE; источник должен существовать в схеме ответа, назначение — объявленное изменяемое состояние того же скалярного типа (text/int32/bool); повтор назначения запрещён. Необязательное действие выполняется над новым состоянием, затем применяется общая проверка и commit. Требуется authenticated SQL rows service без idempotency и приложение без persist. Это консервативное ограничение, не полноценный анализ потоков конфиденциальных данных. Не использовать публичный кеш или пользовательские действия для утечки чувствительных данных.

Runtime проверяет сессию, актуальность результата относительно текущих параметров пути и тела, статус success, поколение и принадлежность данных, наличие кнопки в DOM и видимость, состояние полей. Старые результаты могут оставаться видимыми, но выбор недоступен до новой загрузки. Это не гарантия актуальности БД: серверные FK и compare-and-set last_event остаются обязательными. При выходе очищается непостоянное состояние приложения с remote-pick; при 401 без ожидающего повтора также; при 401 с pending параметры остаются в памяти для повторной авторизации прежнего пользователя. Выход или reload теряет локальный ключ повтора, как ранее. Автоматические обновления и cursor navigation пока не реализованы.

Проверки: 86 Rust tests, включая типы, область видимости, неизвестные поля/цели, дубликаты, persist и auth; 68 прямых HTTP и 27 HTTP из сгенерированного jsdom. Сервисный журнал выбирает заказчика, объект, оборудование, заявку и её версию без ручного копирования; устаревший/отсоединённый выбор отказан, выход сбрасывает поля, транзакционный цикл и replay сохранены. Нет визуальной приёмки настоящего браузера. SQL не менялся, публичный A30 релиз и main не изменены. Новая грамматика — кандидат, требует новый компилятор.

Повторная регрессия A16–A25 и семь alpha-сценариев прошли, включая 319 прямых HTTP-запросов и прежние DOM-тесты.
