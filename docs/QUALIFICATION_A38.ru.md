# A38 — ревизия декларативной платформы

Нормативная основа: [«Описал — получил»](DECLARATION.ru.md). Кандидат A38 поверх A37. Не меняет опубликованные релизы и SedravaSQL. Цель: квалификация перед новым публичным выпуском, а не увеличение количества конструкций языка.

## Найденные недостатки и изменения

1. **Семантический дрейф (целостность).** В A33–A37 ограничения text/int, initial, правила переходов, capture и otherwise могли изменяться без изменения DDL. Существующая история миграций проверяла DDL и имя шага, но не эти правила. A38 вычисляет SHA-256 нормализованного типизированного контракта каждой сущности (domain-contract-v1, имя, упорядоченные поля/типы и, если есть, workflow с initial, event и переходами/capture). Имя шага создания таблицы — d + первые 63 hex-символа хэша (252 бита). Это часть существующего неизменяемого журнала миграций, не новый формат NativeLog. Несовместимые изменения существующего контракта теперь отклоняются при migrate (status/apply) и serve. Метки, заголовки, комментарии, отчёты и представления исключены из контракта, поскольку не меняют правила записи. Порядок полей/переходов считается значимым консервативно; это не семантическое доказательство эквивалентности произвольных программ. Контракт применяется к управляемому проекту в доверенной локальной среде, не является криптографической защитой от оператора, самостоятельно меняющего журнал или низкоуровневый SQL. Добавление сущности в конец сохраняет прежний префикс, если не меняет старые миграции; остальные ограничения A33/A34 остаются.
2. **Остаток черновика после выхода.** В приложении с одной сущностью и без remote-pick правило очистки сессионного состояния не срабатывало. Теперь непостоянные reactive WebApp также очищают черновики при успешном logout и при 401 без pending write. Для неопределённого результата записи сохраняется прежнее намерение повтора только с тем же пользователем. Прежние приложения с persist не сбрасываются новым условием.
3. **Ограниченная проверка пакета.** Неожиданное имя файла/ресурса отвергается сразу, а не после сбора произвольного списка файлов в память. Точность побайтной сверки сохраняется. Это не защита от атак на доверенные каталоги или изменения файлов конкурентным процессом.

## Совместимость

**Намеренная несовместимость с БД экспериментальных A33–A37:** имена шагов формата 2 теперь различаются, даже если DDL совпадает. Не удалять и не перепривязывать такие БД автоматически. Для существующих тестовых данных сохранять исходный компилятор/источники и прежнюю базу; для A38 использовать новый приватный каталог. Поддерживаемой процедуры переноса нет. Старый опубликованный формат 1 A30 сохраняет механизм миграций без изменений. Декларации A33–A37 остаются побайтно прежними, компилятор генерирует новые пакеты; старые проверяемые пакеты должны быть пересобраны новой версией. Никакие пользовательские БД в этом испытании не меняются.

## Проверки

Семь same-DDL изменений: граница строки, диапазон int, предел стоимости, otherwise, capture, initial, ребро перехода. На временной БД проверяются отказ status/apply/serve и побайтная неизменность журнала; изменение меток/комментария принимается без записи. A33 дополнительно проверяет append-only расширение. Для A37 сохранены проверки двух конкурентных записей, идемпотентности, календаря, защиты типов, FK/ролей, полной истории/сумм.

Впервые используется реальный Chromium Headless Shell 141.0.7390.37 (Playwright 1.56.1, Node 20.20.2), в изолированном каталоге тестовых инструментов VDS, без системной установки библиотек. Проверки выполняются только на loopback и синтетических данных; это воспроизводимый тестовый инструмент, не рекомендация применять старый Chromium для внешних сайтов. Первоначальная загрузка браузера с одного CDN оборвалась, альтернативный CDN сработал; пять библиотек распакованы из Ubuntu пакетов в отдельный каталог. Настоящие DOM/layout, вход read/write, отказ reader, создание, XSS-safe текст, выбор, переходы, реактивные итоги и logout. Desktop 1366×900; mobile viewport 390×844 — отсутствие горизонтального переполнения после смены размера, не испытание на физическом телефоне. Скриншоты синтетических данных в evidence. Визуальная проверка верхних областей подтверждает доступность размещения элементов, не полноценную оценку удобства.

## Остающиеся ограничения / release gate

- A38 исправляет два конкретных дефекта и ограничивает проверку пакета, но не является полным аудитом безопасности. Нет публичной многопользовательской эксплуатации, автоматического восстановления, серверного времени/автора события, переноса прежних БД, полноценного управления идентификаторами, общей схемной эволюции и типового CRUD update/delete в format 2.
- UX: длинный экран заявки, ручные ID/дата/курсор, начальные запросы и повторный выбор версии. Это ограничения дальнейшей разработки, не основание выдавать готовый сервис за промышленный продукт. Не добавлять вручную API/SQL/UI ради обхода.
- A37 docs ранее слишком уверенно описывали предел SUM: NativeLog вычисляет i64, UI требует int32; 4096 строк при допустимом модуле 500000 дают максимум 2048000000. Бюджеты обычного и индексного сканирования 4096, превышение бюджета возвращает ошибку. Прямой SQL-ответ вне модели может быть шире int32 и не обязан отклоняться самим движком.
- Перед опубликованием нового alpha: независимая CI на точном коммите (Forgejo, без GitHub Actions), собственная версия и согласованный дистрибутив/проверяемая установка, документация сайта, обновлённые предупреждения о format 2, SHA-256 и проверка скачивания. Не подменять публичный alpha.3 бинарником этого кандидата. Не обещать кроссплатформенность или production readiness.

Результаты финального прогона и точный статус выпуска должны добавляться только после фактической проверки.
