# Sedrava A0 — первый лексер на самом языке

Статус: **экспериментальный учебный прототип**, 23 ноября 2026.
Не полноценный лексический анализатор языка и не самокомпилятор.

## Зачем это нужно

Долгосрочная цель — компилятор Sedrava, написанный на Sedrava,
который умеет собирать собственные исходники. На этапе A0 мы
проверяем более скромную предпосылку: можно ли реализовать
лексическую обработку входного текста **самим кодом Sedrava**,
а не вызывать Rust или Python токенизатор как встроенную функцию.

## Что сделано

- В портативную скалярную библиотеку добавлена функция
  text_at(source, index) -> text: нулевая индексация по **скалярным
  значениям Unicode**, длина результата 1 скаляр. Индекс вне строки,
  включая отрицательный, вызывает ошибку. Это не байтовый доступ
  и не индекс по графемам.
- Операция реализована в Rust-интерпретаторе, Python-эталоне,
  JS-кодогенераторах и исходном Kotlin runtime. Проверена
  Rust и Python/Node-паритетность, в том числе emoji и границы.
  Компилятор Kotlin на VDS не установлен: реальная сборка
  Android runtime остаётся отдельной проверкой.
- examples/self_host/lexer_a0.sdr содержит алгоритм из
  **настоящих Sedrava action step/finish** с состояниями cursor,
  fragment, fragment_kind, start и списком Token. Никакого
  вызова стороннего лексера из программы нет.
- Для проверки текущий CLI последовательно вызывает action step
  ровно по одному разу на каждый символ, затем action finish.
  Цикл/планировщик пока находится **снаружи** Sedrava, поэтому
  это ещё не автономный лексер.

### Поддерживаемая грамматика A0

- ASCII-идентификаторы: латинские буквы, цифры после первого символа,
  подчёркивание;
- ASCII-десятичные целые без преобразования в число;
- знаки: круглые скобки, равенство, плюс, минус, запятая;
- пробел как разделитель;
- позиции — от нуля по символам входной строки.

Нельзя пока использовать кавычки, строки с escape, комментарии,
переводы строк/табуляцию, кириллицу в идентификаторах,
операторы из нескольких знаков, полноценные числа и вложенный
лексический анализ. Строка, где цифры непосредственно переходят
в буквы, отвергается (например, 12a). Неподдерживаемые символы
вызывают явный отказ.

## Запуск проверки

При установленном Rust/Cargo и собранном sedrava-native:

~~~sh
cargo build --manifest-path rust/Cargo.toml --locked --bin sedrava-native
./rust/target/debug/sedrava-native check examples/self_host/lexer_a0.sdr
./rust/target/debug/sedrava-native test examples/self_host/lexer_a0.sdr
python3 scripts/verify_selfhost_lexer_a0.py
python3 -m unittest discover -s tests -p test_platform_stdlib.py
~~~

Сценарий использует Python **только как независимый эталон** и
для запуска внешнего процесса. Исходник тестируемого алгоритма
обязательно остаётся .sdr, а вычисление токенов происходит в
sedrava-native run. Для 13 допустимых входов сверяются типы,
текст, позиции и повторяемость вывода; 8 недопустимых входов
должны дать ошибку.

Пример разбора «sum=42 (next)»:

| kind | lexeme | offset |
| --- | --- | --- |
| identifier | sum | 0 |
| punct | = | 3 |
| integer | 42 | 4 |
| punct | ( | 7 |
| identifier | next | 8 |
| punct | ) | 12 |

## Следующие ограничения и критерии

A1: внутренний ограниченный цикл по символам и безопасные
операции над байтами, без повторяющегося CLI-action снаружи.
A2: полноценные токены Sedrava, Unicode, escape, комментарии,
индексация и диагностические сообщения; сверка с независимым
Rust-парсером на одинаковых корпусах.
A3: AST и проверка типов на Sedrava.
Последующие этапы: IR, генератор и проверка самокомпиляции
stage 1 / stage 2 / stage 3.

Сборка обычных приложений/серверов остаётся через существующий
экспериментальный Rust компилятор. Из этапа A0 **нельзя**
делать вывод, что компилятор написан на Sedrava.

Отслеживание: https://github.com/VasiliiBabkin/sedrava/issues/91

## Статический анализ

Нативный Cargo Clippy без режима -D warnings выполняется; строгий режим -D warnings пока завершается с ошибками в других файлах существующего Rust-ядра (parser, collections, server, site). Это известный технический долг. Данный прототип не заявляется как прошедший строгий Clippy для всего репозитория.
