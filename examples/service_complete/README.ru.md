# Сервисный журнал A37

Рабочий декларативный пример: domain.sdr и sedrava-project.json. Требуется Sedrava 0.12.0-alpha.4. См. PLATFORM_RELEASE_A39.ru.md в комплекте или docs/PLATFORM_RELEASE_A39.ru.md в репозитории. Сборка из корня репозитория: cargo build --manifest-path rust/Cargo.toml --locked --bin sedrava. Добавьте rust/target/debug в PATH. Из каталога примера выполните sedrava test, sedrava build, затем обычные migrate/serve по [инструкции A33](../../docs/DOMAIN_MODEL_A33.ru.md) с новым приватным каталогом данных и auth-file. [Контракт A37](../../docs/SERVICE_DOMAIN_A37.ru.md).

Создайте заказчика, объект, оборудование и заявку. Дату введите в формате YYYY-MM-DD; минуты и стоимость используются только при действии «Записать работу». Выберите заявку из списка или фильтра по статусу, введите новый ID события и комментарий. После операции выберите свежую версию заявки. Загрузите историю и итоги — после последующих записей ранее открытые данные обновятся автоматически. Состояния open/closed, суммы в целых рублях. Только локальные тестовые данные. История сортируется по ID, не по дате. Базы прежних примеров несовместимы.
